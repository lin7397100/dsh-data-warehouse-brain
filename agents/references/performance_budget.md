# 编排层性能预算与优化规范（Performance Budget）

> **版本**：v1.0（2026-11-20 · 衍薪 · 性能优化规范落地）
> **适用范围**：编排器（data-warehouse-brain-team-lead）与全体专家在**单次任务**内的上下文组装、报告构建、交付校验、血缘取证四个环节。
> **不适用**：`knowledge/**`、`observed/lineage/**`、`sg-data-lineage` 技能、三闸门判定逻辑 —— 上述属**血缘体系硬红线**，任何性能优化一律不得触碰（见 §5）。
> **配套**：`agents/references/api_alignment.md`（v2.0 · 派发 API 与 `delegate_expert` 字段）、`agents/references/data_layering_ods_dwd_dws_ads.md`（分层口径）、`agents/references/skill_ownership_governance.md`（owner 治理）。

---

## 0. 根因：瓶颈 100% 在编排层，不在数据层

**2026-11-20 单任务实测（trace `perf_opt_20261120`）**：端到端 **2,140 s（35 分 40 秒）**，而 6 条 SQL **实际执行合计仅 1,098 ms（1.1 秒）** —— 端到端对数据层放大约 **1,900 倍**。

| 序 | 阶段 | 耗时 | 占关键路径 |
|---|---|---|---|
| 1 | P0 意图契约 | 129 s | 6.4% |
| 2 | 三路并行取证（ontology 332 ∥ semantic 263 ∥ **metadata 436**） | 436 s | 21.5% |
| 3 | 确定性编译 | 169 s | 8.3% |
| 4 | 安全审查 | 181 s | 8.9% |
| 5 | 取数执行 | 226 s | 11.2% |
| 6 | 质量闸门 ∥ 出图（302 ∥ 310） | 310 s | 15.3% |
| 7 | HTML 统稿 | **440 s** | 21.7% |
| 8 | J1 返工+校验+台账 | 135 s | 6.7% |

**结论**：优化的对象是**编排层的重复传递、重复构建、重复校验**，不是 SQL、不是数据、更不是血缘覆盖度。本规范四项优化合计 **−835 s**，35.7 min → **≈21.8 min**（见 §6 台账）。

> **执行纪律**：四项优化均为**强制动作（MUST）**，不是建议。任一项未执行即视为该任务编排违规，须在交付回执中显式披露。

## 1. 优化① context_pack 固化（省 ~300 s）

### 1.1 问题实证

8 个专家**每个**都收到 1,500~2,500 字的**自包含** prompt。为保证"独立上下文可执行"，同一批稳定事实被复制 8~24 遍：

- 表结构 8 列清单
- 厂别 9 码白名单
- 「比率不可加」硬约束
- `8000294` 空壳表缺陷
- 时间窗口定义

累计约 **16,000 字**重复传递。每次传递都在重新"讲一遍已知事实"，且**每份副本都会独立漂移**（同一事实出现 3 种措辞即无法仲裁）。

### 1.2 强制动作

1. **P0 意图契约完成后、派发任何专家之前**，编排器 **MUST** 先落盘：

   ```
   observed/context/context_pack_<trace_id>.json
   ```

2. **context_pack 必备字段**（缺一即不合格）：

   | 字段 | 类型 | 内容 |
   |---|---|---|
   | `trace_id` | string | 本次 trace |
   | `window` | object | `{start, end, date_type, edition}` 时间窗口与口径版本 |
   | `facts[]` | array | 稳定事实（表/列清单、行数基线、字段语义），每条带 `source` 溯源 |
   | `constraints[]` | array | 硬约束 HC（如「比率不可加」「半累加维度」），带 `hc_id` |
   | `defects[]` | array | 已实证缺陷（如 `8000294` 空壳、`FACTORY_DIV` 9 码），带 `evidence` |
   | `factory_whitelist` | array | 厂别白名单（9 码） |
   | `created_at` | string | ISO8601 |

3. **专家 prompt 规范**（这是本项的核心收益来源）：
   - **只写**三样：①「读取 `<context_pack 绝对路径>`」② 本次**增量**任务（专家独有、不可从 pack 推导的部分）③ 输出 schema；
   - **正文 ≤ 500 字**（中文按字符计，不含路径与 schema 块）；
   - 绝对路径必须写全（`$env:DSH_HOME\dwb-team/observed/context/context_pack_<trace_id>.json`），禁止相对路径（子专家工作目录不同）。

### 1.3 验收标准

| 项 | 阈值 | 校验方式 |
|---|---|---|
| 单专家 prompt 正文 | **≤ 500 字** | 派发前逐条计数，超限即重写 |
| context_pack 字段完整 | `facts[]` / `constraints[]` / `defects[]` / `window` **四者齐全** | JSON schema 校验 |
| 事实单一来源 | 同一事实在 prompt 中出现 **≤ 1 次**（仅引用，不重述） | 人工/正则抽查 |

### 1.4 禁用反例

- ❌ **把事实再抄一遍进 prompt**（"既慢又易漂移"）—— 这是本项唯一要消灭的行为。
- ❌ 用「上文已说明」等指代替代路径（子专家无上文，必然幻觉补全）。
- ❌ context_pack 只写路径不写内容（空壳 pack 等于没固化，专家仍会自己重新探索）。
- ❌ 每个专家各生成一份自己的 pack（应全团共享同一份 `context_pack_<trace_id>.json`）。

## 2. 优化② ECharts bundle 资产复用（省 ~200 s）

### 2.1 问题实证

composer 每次生成报告，都把 **1,024,740 字节**的 ECharts 5.4.3 bundle **内联**进 HTML（为满足「零 CDN」铁律，`verify_report.js` J1b 校验 `<script src=` / `jsdelivr` / `unpkg` 三者均不得出现）。这是**一次性资产**，却被每次重写 —— 单次报告构建为此多耗约 200 s 的生成与搬运。

### 2.2 强制动作

1. bundle **单次落盘**到版本化路径：

   ```
   assets/vendor/echarts_5.4.3.min.js
   ```

2. 同目录登记 MD5 清单 `assets/vendor/MANIFEST.json`：`{file, bytes, md5, version, created_at}`。
3. composer 构建时 **MUST** 以**字符串拼接**方式从该文件读取并内联：`html = head + '<script>' + bundleText + '</script>' + businessScript`。
4. **禁止**重新拉取（无网/离线环境必然失败）、**禁止**重新压缩/重写 bundle 内容。

### 2.3 验收标准

| 项 | 阈值 | 校验方式 |
|---|---|---|
| 内联段 MD5 一致 | HTML 内联段 MD5 **==** `assets/vendor/echarts_5.4.3.min.js` 的 MD5 | 抽取 HTML 内 `<script>` 首块正文算 MD5 比对 |
| 构建耗时 | **≤ 60 s** | 计时 |
| 字节一致 | 内联字节数 == `1,024,740` | 长度断言 |

### 2.4 禁用反例

- ❌ **改动 bundle 版本却不做 MD5 登记**（MANIFEST 与磁盘不一致，下次构建无法判定复用是否安全）。
- ❌ 用 `assets/echarts.min.js`（无版本号）直接内联而绕过 `assets/vendor/` 版本化路径（版本升级时无法并存回滚）。
- ❌ 为省体积自行 minify（改变组件指纹，图表可能静默失效）。
- ❌ 引入 CDN 兜底（违反 J1b 零 CDN 铁律）。

## 3. 优化③ 官方校验器前置（省 ~135 s 返工）

### 3.1 问题实证

**口径冲突实证**：composer 曾自实现 J1 自检，报 `{{=0 }}=0` → **PASS**；但官方 `scripts/verify_report.js:54-65` 判定 **FAIL**，白跑一轮返工（135 s）。

差异根源（已读源码确认）：

```js
// scripts/verify_report.js:55-64
const scriptMatches = [...html.matchAll(/<script>/g)];
const lastIdx = scriptMatches[scriptMatches.length - 1].index + '<script>'.length;
const bizJs = html.slice(lastIdx, html.indexOf('</script>', lastIdx));
const dblOpen  = (bizJs.match(/\{\{/g) || []).length;
const dblClose = (bizJs.match(/\}\}/g) || []).length;
```

官方校验器取**「最后一个 `<script>` 块」**的正文统计 `{{` / `}}` 字面量，**不排除 inline bundle** —— 而 bundle 被内联在同块时，minified 代码里的 `}}` 会被数进去（本次实测命中 2 个），判 FAIL。composer 自检因只扫业务片段而误报 PASS。

### 3.2 强制动作

1. composer 产出报告后 **MUST 直接调用**官方校验器，禁止自实现：

   ```bash
   node <包根>/scripts/verify_report.js "<报告绝对路径>" <图表数>
   ```

   包根 = `$env:DSH_HOME\dwb-team`。

2. **禁止自实现 J1 / J2 / J3**（含「轻量版」「快速版」「只查业务块」等任何变体）。
3. **口径明示（写入规范即生效）**：业务脚本内**禁止出现相邻 `}}`**；嵌套对象/模板闭合必须用空格拆开书写 —— **`} }` 而非 `}}`**。同理 `{{` 亦拆为 `{ {`。

### 3.3 验收标准

| 项 | 要求 |
|---|---|
| 回执内容 | composer 回执 **MUST 贴官方校验器原始输出全文** |
| 退出码 | **0** |
| 自检声明 | 禁止出现「自检通过」「已确认无残留」等无原始输出的口头声明 |

### 3.4 禁用反例

- ❌ **自写校验逻辑**（口径必然与官方分叉，本次即因此白跑 135 s）。
- ❌ **口头声称"已通过"**（无原始输出即视为未校验）。
- ❌ 为让自检 PASS 而改官方校验器（禁止修改 `scripts/verify_report.js` 的 J1 口径）。
- ❌ 用 `--quick` 跳过 J3 却不声明（快检仅适用于 T2 单指标趋势；首次交付 / T3+ 必须完整模式）。

## 4. 优化④ 血缘取证「静态缓存 + 动态实测」双轨（省 ~200 s，**血缘零损失**）

> ⚠️ **硬红线**：用户明确要求「**不得影响指标血缘、数据血缘等血缘体系**」。**严禁用降低血缘覆盖度换速度**。原「51 表探针精简到 3 条」方案**已被否决**，不得以任何形式复活。

### 4.1 问题实证

三路并行取证中 metadata 一路 436 s 为关键路径（占 21.5%）。拆解可见：**同一批表的列清单、DDL、存储过程源码在任务内被重复拉取**，且**跨任务完全无复用** —— 而这些内容一天之内不会变。可复用的是**结构**，不可复用（也不许省）的是**数据态**。

### 4.2 三层轨道（必须逐层落地）

| 层 | 内容 | 可缓存 | 理由 |
|---|---|---|---|
| **L1 静态元数据** | 表列清单、DDL、存储过程源码、JOIN 条件、SYSCAT 结构 | ✅ **可缓存 24 h**，key 绑**对象版本号**（`ALTER_TIMESTAMP` / `CREATE_TIME`） | 结构不日变；版本一变立即失效 |
| **L2 数据态实测** | 逐日行数、`FACTORY_DIV` 值域、0 行判定、`ZB_CODE` 存在性、**字段级覆盖** | ❌ **禁缓存，一个探针都不许省** | 数据每天变，是血缘可信度核心 |
| **L3 三闸门** | 结构完整 / 链路连续 / 设计态≡数据态 | ❌ **强制实测，禁降级** | 闸门一降级，血缘结论即失效 |

**L1 缓存键规范**：`key = f(对象全名, 对象版本号)`。版本号取 `SYSCAT.TABLES.ALTER_TIMESTAMP`（表）/ `SYSCAT.ROUTINES.CREATE_TIME`（存储过程）。**禁止**用「日期」或「trace_id」做键 —— 那等于把缓存退化为一次性。

### 4.3 四道安全阀（逐条强制）

1. **缓存鉴权**：命中 L1 缓存时，报告 **MUST** 标注
   `静态元数据：缓存命中（TTL 24h，版本 <ver> 未变）`。
   **禁静默使用** —— 未标注即视为隐瞒取证来源。
2. **版本失效**：对象版本号变化 → 该对象缓存**立即作废**，自动回退全量重取；禁止「版本变了还拿旧缓存凑」。
3. **门禁不降**：`field_coverage_rate ≥ 0.90` 的判定**永远基于 L2 实测**，**绝不用缓存值凑数**。缓存只能省"取结构"的时间，不能替"验数据"的结论。
4. **闸门豁免**：任何性能优化**不得**触碰三闸门（结构完整 / 链路连续 / 设计态≡数据态）判定逻辑；PARTIAL / FAIL **必须原样披露**，禁止美化、禁止降级为 PASS、禁止"本次特殊"。

### 4.4 参考基线（本次实测，作为红线锚点）

```
field_coverage = 0.625   <   阈值 0.90
```

即：本次血缘**本来就低于门禁**，已在交付中披露 `[血缘不完整·数据存疑]`。**任何优化都不许让它继续下掉 —— 这是红线。** 优化后 `field_coverage` 必须 **≥ 0.625**；若下降，**无条件回退**本次优化并保留失败样本。

### 4.5 验收标准

| 项 | 要求 |
|---|---|
| L2 探针数 | **== 优化前探针数**（一表一探针，不得减少） |
| `field_coverage` | **≥ 0.625**（不得低于优化前基线） |
| 三闸门 | 判定逻辑字节级未改动；结论与优化前**逐项一致** |
| 缓存标注 | 凡命中 L1 处，均出现版本号与 TTL 标注 |
| 血缘产物 | `knowledge/**`、`observed/lineage/**`、`sg-data-lineage` 技能**零改动** |

### 4.6 禁用反例

- ❌ **「51 表探针精简到 3 条」**（已被否决；减少探针 = 直接降低血缘覆盖度）。
- ❌ 把 L2 数据态结果写进 L1 缓存（数据每天变，等于用旧数据冒充实测）。
- ❌ 以「上次也是这个版本」为由跳过版本号校验。
- ❌ 用缓存值填充 `field_coverage_rate` 的分子（凑数即造假）。
- ❌ 把 PARTIAL 闸门写成 PASS，或删掉 `[血缘不完整·数据存疑]` 披露。

## 5. 血缘体系硬红线（不可协商）

以下内容**一个字节都不许改**，性能优化对其**无豁免权**：

| 禁区 | 路径 / 对象 |
|---|---|
| 血缘知识资产 | `knowledge/**` |
| 血缘实测留痕 | `observed/lineage/**` |
| 血缘技能 | `skills/sg-data-lineage/**` |
| 三闸门判定逻辑 | 结构完整 / 链路连续 / 设计态≡数据态（含 `field_coverage_rate ≥ 0.90` 阈值本身） |

同时**不改**：业务 SQL、口径定义、结论与数值、数据资产。

> 判定方法：优化前后对上述路径做 MD5 全量比对，**任何一项变化即判违规**（见 §7 自检脚本）。

## 6. 优化收益台账

| 序 | 优化项 | 收益 | 实现代价 | 血缘影响 |
|---|---|---|---|---|
| ① | context_pack 固化 | **−300 s** | 一次落盘 + prompt 瘦身至 ≤500 字 | 无 |
| ② | ECharts bundle 资产复用 | **−200 s** | 单次落盘 + MD5 登记 + 拼接读取 | 无 |
| ③ | 官方校验器前置 | **−135 s**（消灭返工轮） | 直接调官方脚本，删自实现 | 无 |
| ④ | 血缘静态缓存 + 动态实测双轨 | **−200 s** | L1 只缓存结构、L2/L3 全量实测 | **零损失**（覆盖度不下掉） |
| | **合计** | **−835 s** | | |

**推算**：`2,140 s − 835 s = 1,305 s ≈ 21.8 min`（35.7 min → ≈21.8 min，**提速 39%**）。

> 收益以**关键路径**计（并行阶段取较慢一路）。单项收益不得叠加重复计量。

## 7. 自检与回滚

### 7.1 交付前自检（逐条必跑）

```bash
# ① context_pack 存在且四字段齐全
python -c "import json,sys;d=json.load(open('observed/context/context_pack_<trace_id>.json',encoding='utf-8'));print([k for k in ('facts','constraints','defects','window') if k not in d] or 'PASS')"

# ② 内联 bundle MD5 一致
python -c "import hashlib;p='assets/vendor/echarts_5.4.3.min.js';print(hashlib.md5(open(p,'rb').read()).hexdigest())"

# ③ 官方校验器（必须贴原始输出 + 退出码 0）
node scripts/verify_report.js "<报告绝对路径>" <图表数>

# ④ 血缘资产零改动（与优化前快照比对）
python -c "import hashlib,os;print('比对 knowledge/ 与 observed/lineage/ 的 MD5 清单')"
```

### 7.2 回滚

| 优化项 | 回滚方式 |
|---|---|
| ① | 删除 `observed/context/context_pack_<trace_id>.json`，恢复自包含 prompt（回退即回到 2,140 s 基线） |
| ② | `cp assets/vendor/echarts_5.4.3.min.js.bak assets/vendor/echarts_5.4.3.min.js`（MANIFEST 同步回滚） |
| ③ | 恢复 composer 自检代码（**不推荐** —— 自检口径已证明与官方分叉） |
| ④ | 清空 L1 缓存目录，强制全量重取（血缘结论不受影响，仅耗时回到基线） |

**回滚判定**：`field_coverage < 0.625` **或** 三闸门结论与优化前不一致 → **无条件回滚**并保留失败样本。
