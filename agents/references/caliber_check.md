# 口径核验五级分级规则（caliber_check v2.0）

> 生效：2026-10-30 ｜ 替代：「未在 `T_ADS_DIM_GZ01` 注册的指标一律禁用」的绝对化表述
> 适用：全部数据类任务（问数 / 报表 / 根因 / 驾驶舱 / 对外交付）
> 权威性：本文件为口径核验唯一权威；与其它文档冲突时以本文件为准

---

## 0. 修订缘由（为什么改）

| 旧规则 | 问题 |
|---|---|
| 「未在 `T_ADS_DIM_GZ01` 注册的指标禁用」 | ① 把"未登记"等同于"不存在"，**有数据但未注册**的指标被直接拒答；② 成本域/存货域指标本就不在 GZ01，一律拒答等于业务不可用；③ 与包内既有设计冲突——`sg-dsl-compiler` 已写明「完全未注册指标转 `sg-adhoc-indicator` 即席构建」，`sg-semantic` 却写「禁止执行，无例外」，**规则自相矛盾** |
| 「成本/存货域禁以 GZ01 判空」 | 方向正确，但被与上一条并列后，被误读为「这些域也不能查」 |

**新原则**：`GZ01` 是**首选索引**，不是**唯一入口**。未注册 ≠ 不可用；未注册只意味着**需要更深一层的核验**。

## 1. L0 前置纪律（不可协商，五级全程有效）

| # | 纪律 | 违反判定 |
|---|---|---|
| A | **禁止以 `T_ADS_DIM_GZ01` 单点判空**得出「无此指标 / 无数据」结论 | 结论作废，重走 |
| B | **禁止猜测口径**；口径不确定时必须在交付中标注不确定项 | 结论作废 |
| C | **禁止编造数值**；无法计算时输出"无法计算 + 缺失环节"，不得填 0 或估数 | 记严重违规 |
| D | 任何交付必须带 **口径来源标记**（见 §5 输出模板） | 交付不完整 |
| E | 取数 SQL 必须由 `sg-development` 编译（主理人不得自写 SQL） | 调度违规，监衡记档 |

> 成本域 / 存货域的特别提示：这两域的指标**主要不在** `T_ADS_DIM_GZ01`。查不到属正常，必须直接进入 L2，**不得**据此判定无数据。

### L4 · 双库均未命中 → 指标新建（四步流水线，缺一作废）

> 触发即**必须组队**，主理人不得自行定义指标。

| 步 | 角色 | 任务 | 产出 |
|---|---|---|---|
| ① 指标设计 | **`sg-metric-builder`（矩衡）** | 按四级指标体系（业务/原子/派生/复合）定义指标：名称、编码、口径六要素（账期/范围/单位/分子分母/过滤条件/版本）、血缘设计、计算逻辑 | 指标卡（含 ZB_CODE 建议值与口径说明） |
| ② SQL/过程开发 | **`sg-development`（淬锋）** | 依据指标卡写 DSL + SQL；落 DWD/DWS（必要时 ADS）；涉及批量则出存储过程 | 可执行 SQL / 存储过程 + 性能评估 |
| ③ 数仓建模与规范审查 | **`sg-5s-dev`（规枢）** | 按两本规范完成 ODS→CDM→ADS→API 全链路建模、命名合规、分级分类与安全审查；复用 `skills/sg-5s-dw-modeling` 的 16 步流水线 | 建模文档 + 合规审查结论 |
| ④ 注册回流 | **`sg-semantic-batch-register` / `sg-kpi-sql-config`** | 写回 `T_ADS_DIM_GZ01`（ZB_CODE/ZB_NAME/SQL1/maturity）+ 口径卡写 WeKnora 指标体系库 | 注册完成凭据 |

**两本规范的物理载体**（`sg-5s-dev` 执行时必须 Read）：

- 《大数据5S平台开发规范》→ `knowledge/5s/流程_5S平台开发流程ODS-API.md` + `skills/sg-5s-dw-modeling/SKILL.md`（16 步 xData 维度建模：ODS→CDM→ADS→API）
- 《数成开发》→ `knowledge/5s/数成_用户手册2024Q3.md`

**轻量变体（临时即席问数，不建表）**：
若用户只是临时问一次、不需要固化为资产 → 走 `sg-adhoc-indicator`（即席指标构建引擎）：优先复用已有 DWD/DWS，反之重写 DSL 与 SQL，**先出结果再并行固化**为语义层/指标体系资产。此路径不需要走完四步，但**结果同样必须标注「即席构建 · 未注册」**。

> **2026-11-02 纪律补强 · 零起点问数统一约束（五条）**：
> 1. **必须组队**：零指标信息起点（无 ZB_CODE / 无口径 / 用户只给一段自然语言）**必须组队多专家并行**，最小配置 `sg-semantic`（铨度·锁口径）+ `sg-development`（淬锋·编译 SQL）+ `sg-quality`（砺真·闸门）+ `sg-5s-dev`（规枢·5S 规范建模）。**编排器（主理人）禁止代写 SQL、禁止内联判定口径**——与「T2a 趋势手搓下钻」同类违规，统一修复。
> 2. **先过指标卡**：零起点必须先经 `sg-metric-builder` 的「业务语言→指标卡」解析器产出标准指标卡（口径六要素：度量单位/统一口径维度/通用限定条件/计算逻辑/计算方式/来源表），再据此出 SQL；**禁止跳过解析直接写 SQL**（见 `agents/sg-metric-builder.md` 核心能力 0）。
> 3. **K7 先行**：建模前**必须查 weknora K7**（`d12f3c32-bf50-41cc-8be8-77af4c45bb35`）5S 规范与指标开发步骤；未查即建模记违规，产物标注 `[未依规范·存疑]`。
> 4. **护栏不可绕过**：即席 SQL 必须经 `sg-dsl-compiler` 编译 + 三查（语法 / 表存在性 / 合理性）+ `sg-quality` 闸门；**禁止裸写裸出**（见 `skills/sg-adhoc-indicator/SKILL.md` 注意事项 6–8）。
> 5. **三标签交付**：交付**必须**标注「即席构建·未注册·待实据核验」，禁止以确定值口径呈现。

### L5 · 无法构建 → 如实说明

输出格式（三要素缺一不可）：

```
【无法计算】<指标名>
【缺失环节】<数据源缺失 / 权限不足 / 口径不可判定 / 业务规则未定义>
【解锁路径】<需 <角色/部门> 提供 <具体材料>，预计可在 <环节> 解除阻塞>
```

**禁止**：填 0、估数、用其他指标替代后不加说明、静默跳过该指标。

## 3. 根因分析与数据质量异常：主理人必须主动派质量专家

> 「主理人是编排器，不是分析师」——诊断类任务一律不得自行下结论。

| 触发词 / 场景 | 强制动作 | 违规判定 |
|---|---|---|
| 为什么 / 原因 / 异常 / 归因 / 波动 / 下滑 / 排查 / 诊断 / 溯源 / 追溯 / 下钻 | 主理人 **`delegate_expert` 派 `sg-quality`（砺真）主导**（Phase 0 指标类型判定 → §12 归因方法论 → 全链路结论） | 主理人自行诊断 = 调度违规，监衡记档 |
| 数据质量异常：空值 / 重复 / 负数 / 量纲跳变 / 批次缺失 / 勾稽不平 / 同日多次加载 | 同上，必须派 `sg-quality`；跨基地污染风险时**同时**激活 `sg-supervisor` 观察者旁路 | 同上 |
| 涉及多基地 / 跨厂对比 | 追加 `sg-supervisor` 强制监察（发现厂别不一致有权中断回退） | 未激活 = 编排器失职 |

**判定基准**：主理人可以先做"是否异常"的**触发判断**（例如看到数值为 0、为空、环比 ±50%），但**解释与归因必须来自 `sg-quality`**，主理人只做汇总与仲裁。

## 6. 反例（明确禁止）

| 反例 | 为什么错 | 正确做法 |
|---|---|---|
| 「查不到该指标，无数据」 | 只查了 GZ01 就判空 | 继续 L2 血缘 → L3 知识库 |
| 「成本指标未注册，不能查」 | 成本域本就不在 GZ01 | 直接进 L2（`sg-cbprod-warehouse` 决策树 + 成本域权威手册） |
| 主理人自己写 SQL 算出来就交付 | 越权，无质量校验 | 派 `sg-development` 编译 + `sg-quality` 校验 |
| 指标查不到就临场编个公式 | 编造口径 | 走 L4 四步新建，或 L5 如实说明 |
| 数值为 0 就直接说"产量为 0" | 可能是加载缺失 | 派 `sg-quality` 判定是"真 0"还是"缺数" |
| 根因结论由主理人直接给出 | 越权诊断 | 派 `sg-quality` 主导，主理人只汇总 |
