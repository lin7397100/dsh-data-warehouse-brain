# 概念契约（Concept Contract）

> 本文件定义数仓智脑专家团核心概念的**严格分层与边界**，消除「本体/语义模型/表/指标/实体/对象」六词混用与本团特有的 L1~L4 双轴冲突。
> 版本: v1.0 · 2026-11-05 · 根据整改方案 P1-6（A7 采纳）

---

## 一、六概念严格分层（自顶向下）

| 层 | 概念 | 一句话 | 本团对应物 | 关键约束 |
|---|---|---|---|---|
| 1 | **本体（Ontology）** | 知识蓝图（TBox）：定义「有哪些实体类型、属性和关系规则」 | K5 本体库 `ONT-本体-*` / `sg-ontology` | **只含类型与规则，不含海量实例数据** |
| 2 | **语义模型（Semantic Model）** | 可运行施工图：把本体绑定到数据源（表/字段/方言）+ 定义计算逻辑 | `knowledge/CONTRACT.md` §5 语义资产 | **本体 + 数据绑定 + 计算逻辑 + 可执行性** |
| 3 | **表（Table）** | 数据的货架：逻辑与物理的交界 | DB2 96 schema / 9167 表 + 4061 条物化 SQL | 一张表 ≠ 一个实体；表是被动的，不携带业务语义 |
| 4 | **指标（Metric）** | 派生业务度量（成品）：基于表聚合/计算的度量值 | ZB_CODE 锚定的 6077 KPI + 6182 registry | **非实体、无唯一标识**；定义独立于任何物理表；物化汇总表仅为性能优化 |
| 5 | **实体（Entity）** | 被指称的事物：贯穿多层的同一指称 | 本体四元组的 Entity / Order / Customer | 类型回答「有哪一类」，实例回答「是哪一个」；实例可被唯一标识 |
| 6 | **对象（Object）** | 实体在系统中的具体化身 | Python 实例 / JSON 节点 / SQL 返回的一行记录 | 绑定于特定技术栈 |

> ⚠ 关键区分：**指标（Metric）≠ 实体**。指标是聚合计算结果，没有`id`、不能被独立指称。本团 `knowledge/CONTRACT.md:102-114` 曾将 `metrics[]` 纳入本体四元组并为每条指标合成 `id:"M_2000514"`——这**违反了本契约**，应在语义模型层单独定义指标绑定而非并入 TBox。该矛盾已纳入整改方案 P1-6（A7）修复范围。

## 二、本团特有的 L1~L4 双轴消解

> 背景：本团存在两套完全不同的 L1~L4 编号体系，在生产中多次造成混淆（上一轮实战需人工拆两表才消解）。

| 轴 | 含义 | L1 | L2 | L3 | L4 | 权威文件 |
|---|---|---|---|---|---|---|
| **指标层级轴** | 指标在四级体系中的层级 | **原子** | **派生** | **复合** | **业务** | `sg-metric-builder.md`、`sg-indicator-system` |
| **数仓分层轴** | 数据仓库的物理/逻辑分层 | **T_ADS** | **T_DWS** | **T_DWD** | **T_ODS** | `sg-metadata`、`sg-data-lineage`、第零铁律 |

**硬约束**：
- 指标层级轴使用 **「L1原子 / L2派生 / L3复合 / L4业务」**，**禁止**用 L1~L4 指代数仓分层。
- 数仓分层轴使用 **「ADS / CDM(DWS+DWD) / ODS」** 或明确写 **「T_ADS 层 / T_DWD 层」**，**禁止**混淆。
- 文档中若同时涉及两轴，必须显式标注属于哪一轴，例如 `指标层级轴 L1 = 原子指标`、`数仓三层：ADS → CDM → ODS`。

## 三、团队内部简称规范

| 常见混用 | 正确表述 |
|---|---|
| "这个指标就是那张汇总表" | **指标是计算结果，表是数据载体**——汇总表只是物化缓存 |
| "本体建模/语义层构建混用" | 本体建模 = 定义「知识蓝图」（`sg-ontology` 主责）；语义层构建 = 把蓝图绑到物理表 + 配计算公式（`sg-semantic` 主责） |
| "L1 查 T_ADS" | L1 是指标层级（原子指标），不是数仓层——应写「查 ADS 层 / T_ADS_DIM_GZ01」 |
| "这个指标的血缘" | 区分：**物理血缘**（ODS→ADS 的表级链路，`sg-metadata`）vs **指标血缘**（原子→派生→复合，`sg-metric-builder`） |

## 四、消费纪律

1. **所有交付文档、报告、Agent prompt 中，使用本契约定义的六概念分层**。
2. **新增指标能力时，禁止混用 "L1~L4" 指代数仓分层**——这是本团已知的反复事故，再犯记为命名违规。
3. **指标定义必须独立于物理表**：ZB_CODE 为唯一锚点，不得用 `M_<ZB_CODE>` 式本体实体 ID。
4. 本文件为 `members_guidance.md` 的补充概念篇，编排器在「不确定概念边界」时 Read。
