# 企微通道交付规范（WeCom Channel Contract）

> 生效：2026-10-30 ｜ 依据：Claw 通道日志实测（929 步 / 515K tokens / 两次 4 分钟阻塞压缩 / 技能索引丢 42 条）
> 适用：企微机器人、Claw、任何无 UI 的长连接通道 ｜ 桌面端可裁剪使用

---

## 一、通道差异（必须先认知，否则所有优化失效）

| 维度 | 桌面端 | 企微通道 | 后果 |
|---|---|---|---|
| 等待感知 | 有进度条/工具卡片 | **只有"对方正在输入"** | 静默 4 分钟 = 用户认为挂了 |
| 上下文 | 可开新会话 | 单会话长期累积（实测 929 步） | 每轮重发 50 万 token |
| 附件 | 直接预览 | 需 `media/upload` 后发送 | 1.1MB HTML 无法"看一眼" |
| 技能索引 | 143 条可全载 | **只渲染 101 条，丢 42** | 模型看不到需要的技能 |

---

## 二、三节拍交付（硬性）

### 节拍 1 · ACK（首响 ≤ 5 秒）

收到任务后**立刻**回三行以内，不做任何取数：

```
收到：<一句话复述任务>｜预计 <N> 分钟｜完成发结论卡+附件
```

禁止：先查半天再回话；禁止"正在为您查询，请稍候"式空话超过 5 秒。

### 节拍 2 · 进度（每 60 秒一条，最多 5 条）

| 时点 | 内容模板 |
|---|---|
| 取数完成 | `已取数：<N> 行，<M> 个基地` |
| 断言完成 | `校验通过 <x>/<y>，标记 <z> 项` |
| 渲染完成 | `报告已生成，正在上传附件` |
| 压缩/重试中 | `上下文压缩中，约 1 分钟，任务未中断` |

> 关键：**压缩与重试必须外显**。日志里 `blocking compaction` 期间完全静默，是"异常"体感的主要来源。

### 节拍 3 · 交付（结论卡 + 附件）

```markdown
**结论**：<一句话，含数值与日期>

| 项 | 值 |
|---|---|
| 口径 | ZB_CODE / 成熟度 |
| 范围 | 基地 / 期间 |
| 校验 | 断言 x/y 通过 |

**数据限制**：<逐条，无则写「无」>
**附件**：<文件名>（<大小>）
```

硬性：**结论必须在消息正文里说完**，不能只发附件让用户自己点开。

## 三、会话生命周期（治"越用越慢"）

| 触发 | 动作 |
|---|---|
| 单会话 ≥ **60 步** 或 ≥ **30 分钟** | 归档：写 ≤800 字状态纪要（已得结论 / 待办 / 产物路径），开新会话续跑 |
| 单轮输入 > **80K** tokens | 先摘要再发；禁止把全量历史直传 |
| 收到新任务但会话已有 ≥3 个已完成任务 | 直接开新会话，不继承上下文 |

> 实测：10-29 会话 929 步、input 515,163 tokens、缓存命中仅 19,968 —— 说明每轮几乎全量重算。归档阈值必须硬执行。

---

## 四、上下文预算（配合 models.json）

| 水位 | 动作 |
|---|---|
| 40K | **主动摘要**（把已完成步骤压成一行），不等到阻塞 |
| 80K | 强制摘要 + 只保留当前步骤上下文 |
| 91.8K | 平台硬顶（100K prompt − 8K 输出），到此必失败 |

配套改动：模型上下文上限由运行时的 profile 配置决定 —— DSH 下见 `~/.dsh/profiles/desktop/cordis.patch.yml` 的模型节点（历史记录：Qwen3.6-27B `maxInputTokens` 由 `80000` 调至 `100000`，模型实测 `max_model_len=262144`，受平台 100K 硬顶约束取上限）。

## 五、技能白名单（治"42 条被丢"）

企微通道只加载 **≤ 40 个技能**，否则索引超渲染预算，后 42 条直接对模型不可见。

**必选 12 个（缺一不可）**：

`sg-intent` · `sg-intent-parse-dispatch` · `sg-semantic-layer` · `sg-materialized-sql` · `sg-trend-quick` · `sg-db2-executor` · `sg-calc-error-guard` · `sg-qa-render` · `sg-report-composer` · `sg-wecom-doc` · `sg-supervisor` · `sg-cbprod-warehouse`

**按需 3 个（域触发时加入）**：`sg-gzprod-warehouse`（生产域深查）· `sg-data-lineage`（血缘追溯）· `sg-cockpit-report`（驾驶舱）

**其余技能不进企微通道**，由桌面端或按需动态加载承载。

> 白名单不是删技能，是控制**首屏可见集**；命中白名单外需求时，用 `sg-intent` 路由到对应技能名再加载。

## 六、附件投递

| 体积 | 处理 |
|---|---|
| ≤ 2MB | `media/upload` → `send_file_to_user` / `send_file_to_group` 直投 |
| 2–10MB | 转 PDF 或长图后投递 |
| > 10MB | 只发摘要 + 落地路径，让用户到桌面端取 |

**禁止**：在会话里回显 HTML/SQL 源码；用 `send_text` 发送超过 4000 字的长文；把附件内容再贴一遍。

通道隔离铁律不变：HTTP 上传的 `media_id` 只能走 HTTP 通道发送，经 WebSocket robot 发会报 **40007**。

---

## 七、异常兜底（出现即按此走）

| 现象 | 处理 |
|---|---|
| 触发阻塞压缩 | 立即发节拍 2 的"压缩中"消息，压缩完成后继续，不重开任务 |
| 单次模型响应 > 3 分钟 | 发"仍在生成"心跳，继续等；> 8 分钟则中止并回退到更小步骤 |
| 模型返回中断/重试 | 不重复解释，直接续跑当前步骤；连续 2 次失败才告知用户 |
| 上下文将满 | 归档续跑（§三），**不要**在同一会话里硬撑 |
| 工具调用无 toolCallId | 记录后继续，UI 广播失败不影响执行 |

## 八、验收线

| 指标 | 目标 |
|---|---|
| 首响 | ≤ 5s |
| 静默间隔 | ≤ 60s（压缩/重试期间必须有话说） |
| 单会话步数 | ≤ 60 |
| 单轮输入 | ≤ 80K |
| 技能可见数 | ≥ 白名单 12（不得被截断） |
| 附件投递成功率 | 100%（≤2MB 直投） |
