# 专家团记忆知识库规范（K8 · 2026-11-16 v1.0）

> 这是专家团「持续学习进化」的核心基础设施。K8 = 记忆知识库，存对话中学到的事实、教训与改进。
> 主责写入：衍薪 sg-skill-evolution（会话后自动提炼）+ 各专家（主动写入）
> 主责检索：全体专家在每次任务开始时检索 K8（hybrid_search 相关记忆）

## 一、K8 知识库最优配置

| 配置项 | 推荐值 | 理由 |
|---|---|---|
| `chunk_size` | **512** | 记忆条目通常 150-400 字，512 确保一条记忆一个 chunk，不割裂 |
| `chunk_overlap` | **64** | 相邻记忆有上下文关联时轻度重叠 |
| `embedding_model_id` | **BAAI/bge-large-zh-v1.5** | 与 K1-K5 一致，sentence-transformers 5.6.0，中文语义最优 |
| `summary_model_id` | 同主模型 | 自动摘要用于快速判断记忆相关性 |
| `rerank_model_id` | bge-reranker-v2-m3 | 检索后精排，确保最相关记忆排第一 |
| `enable_status` | **enabled** | 必须开启，否则知识不会被向量化 |
| `parse_status` | 监控直到 **completed** | 新文档摄入后必须等向量化完成才能检索到 |

## 二、记忆内容四元组格式（标准模板）

每条记忆写入 K8 时，必须用以下格式（Markdown）：

```markdown
# {触发场景 · 一句话}

**类型**：{决策/教训/发现/纠错/规则固化}（五选一）
**触发时间**：{YYYY-MM-DD HH:MM}
**涉及指标/表/域**：{ZB_CODE 或 T_xxx 或 域缩写}

## 触发背景
{用户问了什么 / 专家团做了什么 / 出了什么问题——2-3 句}

## 决策/行动
{当时怎么处理的——2-3 句}

## 结果
{处理后的效果——数值化的更好，如'准确率从 X%→Y%'}

## 教训/规则
{下次遇到同类场景应该怎么做——这是检索后直接指导行为的核心字段}

## 关联
- 相关指标：{ZB_CODE-1, ZB_CODE-2}
- 相关表：{TABLE-1}
- 相关知识库：{K1/K2/K3/K5}
```

## 三、五类记忆的写入触发条件

| 类型 | 触发条件 | 写入者 |
|---|---|---|
| **教训** | 用户纠正了专家团的错误（口径/表/JOIN/层选择错） | 砺真（质量裁决后）+ 衍薪（提炼） |
| **发现** | 探索分支发现了新的表/字段/关系/口径（之前未知） | 铨度/构枢/舆图 |
| **决策** | 用户确认了一个重要的技术选择（选哪张表/哪个版本/哪种算法） | 淬锋/矩衡 |
| **纠错** | 烟测/评测中发现 FAIL 并修复后 | 衍薪（评测归因后） |
| **规则固化** | 重复 ≥2 次的口头约定，正式写入规范文件后 | 衍薪（重复模式识别） |

## 四、检索策略（专家团如何使用 K8）

### 4.1 必检时机（每次任务都查）
- **GATE-Q 辨枢产出 IntentContract 后**：用 `{指标名} {域} {基地}` hybrid_search → 检查是否有相关教训
- **淬锋编译 SQL 前**：用 `{表名} JOIN {表名}` hybrid_search → 检查是否有 JOIN 教训
- **铨度设计 DWD 清洗规则时**：用 `{ODS表名} 清洗` hybrid_search → 检查是否有清洗教训

### 4.2 检索指令模板
```
hybrid_search(kb_id="K8_MEMORY_ID", query="{意图摘要 核心指标 域 基地}", match_count=5)
```

### 4.3 检索结果消费规则
- 检索到的记忆必须**在后续步骤中引用**（不能只查不用）
- 若记忆与当前场景高度匹配但未遵循 → 砺真降级该步产出
- 即使记忆"看起来不相关"，也需快速扫读前 3 条以防遗漏

## 五、K8 与现有知识库的分工

| 知识库 | 存什么 | 更新频率 | K8 是否会引用 |
|---|---|---|---|
| K1 表结构 | 静态：表定义、字段、备注 | 表结构变更时 | ✓ 表变更记忆写入 K8 |
| K2 存储过程 | 静态：过程源码、血缘 | 过程变更时 | ✓ 过程行为变化写入 K8 |
| K3 指标体系 | 半静态：指标口径、公式、版本 | 新指标注册/口径变更时 | ✓ 口径演变记录写入 K8 |
| K4 业务规则 | 静态：校验规则、过滤条件 | 规则变更时 | ✓ 规则因教训而改时写入 K8 |
| K5 本体建模 | 半静态：objects/relations/functions | 本体变更时 | ✓ join_key 发现写入 K8 |
| **K8 记忆进化** | **动态：对话中学到的教训与发现** | **每次任务后** | — |

## 六、记忆生命周期管理

| 阶段 | 动作 |
|---|---|
| **写入** | 任务结束后衍薪扫描对话，提炼五类记忆 → 写入 K8 |
| **引用** | 后续任务起手检索 → 命中则引用 |
| **强化** | 同一教训被检索 ≥3 次且每次都正确引导 → 标记 `validated` |
| **固化** | `validated` 的记忆与现有规范冲突时 → 更新规范文件，记忆降级为"已固化注释" |
| **淘汰** | 记忆对应的规范已更新 → 记忆状态改为 `superseded`，保留但不优先检索 |
| **过期** | 超过 6 个月未被检索 → 标记 `archived`，保留但提示时效风险 |

## 七、写入示例（真实记忆单元）

```markdown
# 本部铁水耗指标 1600207 注册码≠存储码 6012600

**类型**：发现
**触发时间**：2026-10-10
**涉及指标/表/域**：1600207 / 6012600 / GZPROD.铁水耗  / T_DWS_FACT_ZZGZ_LG01

## 触发背景
根据指标注册表查泉州铁水耗 ZB_CODE=6042700 去 T_DWS_FACT_ZZGZ_0003 取数，返回空。
经排查发现该指标实际落 T_DWS_FACT_ZZGZ_LG01，且实际存储码为 6012600。

## 决策/行动
改为查 T_DWS_FACT_ZZGZ_LG01 表，用 ZB_CODE='6012600' 过滤。

## 结果
数据正常取回。确认 GZ01 指标注册码 ≠ 存储码，且钢铁料耗类指标落 LG01 不在 0003。

## 教训/规则
查 ZB_CODE 前必须先确认该指标对应的物理表落地位置——注册码和存储码可能不同。
铁水耗/钢铁料耗 → 查 T_DWS_FACT_ZZGZ_LG01（不是 0003）
本部合计码 BF10 = BF11+BF12+BF16；泉州 BF20 = BF23+BF24+BF25

## 关联
- 相关指标：1600207, 6042700, 6012600
- 相关表：T_DWS_FACT_ZZGZ_LG01, T_DWS_FACT_ZZGZ_0003
- 相关知识库：K3
```
