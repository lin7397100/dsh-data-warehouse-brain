### 生产域异常自动检测路由（强制 · 2026-10-19 新增）

当用户意图命中以下任一模式时，编排器**必须加载 `sg-gzprod-anomaly-detect` 技能**（砺真 sg-quality 挂帅）：

- "生产有没有异常 / 指标不正常 / 今天数据怪不怪"
- "产量异常 / 铁水产量怎么掉了 / 钢产量下降"
- "燃料比偏高 / 铁水耗升高 / 成材率下降"
- "查异常指标 / 自动巡检 / 扫一遍生产指标"
- "XX 指标波动 / XX 指标偏离"

**路由决策树**：

```
异常类问法 →
  ├─ "自动扫/巡检/整体/全量" → L1 六组全量扫描 → A/B级→组队根因 → HTML报告
  ├─ "XX指标异常/为什么" → Step 2 单指标判定 → A/B级→Workflow B根因 → 报告
  ├─ "今天生产正常吗" → 六组快扫(仅同环比) → 无异常→"正常" 有异常→展开
  └─ 报表导出时数据异常 → 自动嵌入异常标注 → 标记不正常的sheet/指标
```

**执行链（不可跳步）**：

1. **加载技能** → 编排器先 Read `skills/sg-gzprod-anomaly-detect/SKILL.md`
2. **就绪门禁** → 查铁前/炼钢/轧钢三大链 DWS 批处理当日执行状态（查 `sg-gzprod-warehouse` 域知识取过程清单 → `T_PUB_JOB_LOGS` 当日 `IS_SUCCESSFUL='Y'`）
3. **异常扫描** → 逐组判定六组指标（五类检测 × 六组 = 30 条规则并行）
4. **A/B 级 → 强制同一轮组队多专家并行**（同一消息内 5 条 `delegate_expert`；编排器一票否决自己偷懒 · 2026-10-19 用户整改）
   - 检出 A/B 级异常后**必须立即组队派发**五专家（砺真+鼎元+铨度+舆图+监衡，建卡 `todo_write` 五张 + 同一消息内 5 条 `delegate_expert`），走 team-lead.md §11 六步追溯
   - **绝对禁止**在组队派发之前输出「可能方向/概率排序/需进一步查证」等非确定性结论就结束本轮
   - **绝对禁止**以 `confidence < 0.6` 或 `[证据不足]` 结尾的初步分析作为 A/B 级交付物 → 这等于半成品当成品
   - 编排器必须按 `sg-gzprod-anomaly-detect` §3 的 7 条自检清单逐条确认，缺一不得结束
   - 违例后果：整份报告作废，由监衡记录编排器违规
5. **报告产出** → 明鉴(sg-insight) + 若溪(sg-zhishu-report-composer) 联合产出 HTML 诊断报告

**根因证据铁律**（与 §10/§11 同级生效）：
- 禁止模糊措辞 / 精准定位到 SCHEMA.TABLE.COLUMN / 差异量化 / 三层埋点缺一不可
- 生产域语义方向：**升=优(红)、降=劣(绿)**。渲染时必须标注方向箭头
- 基地严格区分（先查 T_ADS_DIM_GZ01 取 FACTORY_DIV + SQL1 确认范围）
- 合计码陷阱：BF10/BF20 等合计码与分炉混 SUM 必翻倍
- `T_DWS_FACT_ZZGZ_*` 系列末次装载 2025-06-30（已停更），查当期为空判为停更非缺数

**与成本域的分工**：`sg-gzprod-anomaly-detect`（生产域）与 `sg-anomaly-detect`（成本域）双哨兵互补：
- 生产域=量/效率/技术指标波动 → 侧重「是什么变了」
- 成本域=金额/价差/结构差 → 侧重「为什么会亏/赚」
- 两域可联动：生产产量异常 → 触发对应产线的成本异常排查（量差传导成本）
