# 快车道响应模板（Fast Lane Response Template）

> **生效**：2026-10-29 ｜ **适用**：`fast_lane: true` 的全部纯数值查询
> **目的**：固定四段式输出，保证快车道交付一致、可核验、且**绝不溢出为报告**

---

## 一、准入判定（主理人在 Step 0 执行）

四条件**全部满足**才进入快车道：

| # | 条件 | 判定 |
|---|---|---|
| ① | 纯数值查询 | 不含：根因 / 为什么 / 原因 / 异常 / 归因 / 变化分析 / 波动分析 / 排查 / 诊断 / 溯源 / 追溯 / 下钻 / **趋势 / 分析 / 预测 / 总结 / 评价 / 建议** |
| ② | 指标数 ≤ 3 | `entities.metrics.length <= 3` |
| ③ | 单日或单期值 | 非「近N日 / 本月 / 逐日」序列诉求 |
| ④ | 未要求报告 | 不含：报告 / HTML / 图表 / 可视化 / 看板 / 文档 |

**判定结果必须写入 `StructuredInstruction.fast_lane: true|false`**，不得省略。

---

## 二、响应模板（四段式 · 唯一合法格式）

```markdown
**<指标中文名>**：<数值> <单位>（<数据日期>）

| 项 | 值 |
|---|---|
| ZB_CODE | <编码> |
| 指标全名 | <ZB_NAME> |
| 厂别 | <FACTORY_DIV> |
| 成熟度 | <draft / certified> |
| 置信度 | <0.00~1.00> |

**血缘**：<T_ODS_*> → <T_DWS_*> → <T_ADS_*>（过程：<CREATER>）

**数据限制**：<如「罗源分母塌陷，管理动作应查产量」/「泉州该指标无趋势解释力」/「无」>
```

### 模板要点

| 段 | 必含 | 说明 |
|---|---|---|
| **第 1 段 数值** | 指标名 + 数值 + 单位 + 日期 | **一行说完**，直接给答案，不做铺垫 |
| **第 2 段 口径卡** | ZB_CODE / 全名 / 厂别 / 成熟度 / 置信度 | 五字段固定表格，`maturity=draft` 必须显示。**数值来源**：`sg-materialized-sql` 从物化 SQL 文件头部注释（MATURITY/CALIBER_SOURCE/CONFIDENCE）提取，禁止硬编码或编造（P1-3） |
| **第 3 段 血缘** | 一行链路 + 产出过程 | 让用户能自己复核 |
| **第 4 段 限制** | 数据限制 / 已知问题 | 无则写「无」，不得省略此行 |

## 三、五项禁止（出现任一即违规，监衡记档）

| # | 禁止 |
|---|---|
| 1 | ❌ 生成 HTML / 图表 / 看板 / 抽屉 |
| 2 | ❌ 做归因分析 / 根因分析 / Mix-Rate-Cross 分解 |
| 3 | ❌ 做预测 / 趋势外推 / 同比环比趋势解读 |
| 4 | ❌ 写总结 / 评价 / 建议 / 决策推荐 |
| 5 | ❌ 派发 sg-insight / sg-zhishu-report-composer / sg-zhishu-dashboard-designer |
| 6 | ❌ 加载 `indicator_registry.json` 全量（4.68MB，只用 `indicator_index.json`） |

---

## 四、必须保留的多专家协同（不可降为单人）

快车道**不是单人任务**，最少 5 位专家参与：

| Step | 专家 | 职责 | 耗时预算 |
|---|---|---|---|
| 0.5a | sg-ontology（鼎元） | 本体核验（weknora K5 单条命中） | ≤ 5s |
| 0.5b | sg-semantic（铨度） | 语义核验（口径卡摘要） | ≤ 10s |
| 0.6 | sg-governance（守钧） | SQL 形态预检（仅 SELECT/WITH） | ≤ 3s |
| 0.7 | sg-development（淬锋） | 取数（sg-db2-executor 双通道） | ≤ 15s |
| 0.8 | sg-quality（砺真） | 数值三查（零值/量级/离群） | ≤ 5s |

> 0.5a 与 0.5b **必须并行下发**（同一消息内两条 `delegate_expert`；建卡用 `todo_write` 各记一笔）。
> **双轨留痕（铁律 A）**：0.5a / 0.5b 两张卡并行置 `in_progress`；0.6~0.8 每步回执后 `todo_write` 推进一项，收尾全部 `completed`。只写台账不刷面板 = 面板冻结为开工快照，属交付缺陷。

---

## 五、降级与异常处理

| 情形 | 处理 |
|---|---|
| weknora 不可达 | 0.5a/0.5b 各自回退本地（`knowledge/design/ontology/`、`semantic/`），标注「降级核验」 |
| 指标未命中 `indicator_index.json` | 退出快车道，按完整流程走 Step 1 |
| 用户问法含口径歧义 | 强制派发 sg-semantic 做口径核查，不得主理人自行判断 |
| SQL 双通道均失败 | 如实告知「当前环境无 DB2 MCP 且未配置 token」，**禁止编造数值** |
| `confidence < 0.6` | 标注「置信度偏低」但**仍交付数值**（快车道不因低置信拒交） |

---

## 六、用户追加请求的处理

快车道交付后，用户若说「出个报告 / 分析一下 / 为什么」：

**视为新任务**，重新走 Step -2 判定，此时 `fast_lane` 应为 `false`，进入完整流程（含报告）。

**不得**在同一任务内把快车道输出扩展成报告。

## 七、示例

### 示例 1：标准快车道

**用户问**：昨天本部钢铁料耗多少

**响应**：
```
**本部钢铁料耗**：1054.91 kg/t（20261027）

| 项 | 值 |
|---|---|
| ZB_CODE | 1600213 |
| 指标全名 | 本部经营日报(1)_炼钢_钢铁料耗_日平均 |
| 厂别 | 管控中心 |
| 成熟度 | draft |
| 置信度 | 0.95 |

**血缘**：T_ODS_TMMSM21 → T_DWS_FACT_ZZGZ_LG01 → T_ADS_DIM_GZ01（过程：P_DWS_FACT_ZZGZ_0003）

**数据限制**：maturity=draft，未经业务人工校准；本部含 -1 修正，跨基地对比需声明
```

### 示例 2：应退出快车道

**用户问**：昨天本部钢铁料耗多少，为什么比前天高了

→ 命中「为什么」+「比前天」（变化分析）
→ `fast_lane: false`，进入完整流程（根因分析 + 报告）
