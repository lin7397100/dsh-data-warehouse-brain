# 三令牌护栏 + MQL 隔离 + 金标准回归闭环（源自 Data Agent 调研 · 2026-11-16 提炼）

> 来源：《Data Agent 深度调研报告（2026版）》4.4 节（基于 DeepSeek Harness 的确定性 Data Agent 蓝图）
> 本文件为淬锋（编译）、守钧（治理）、砺真（质量）、铨度（语义）的共同护栏规则源。

## 一、两段式隔离：NL → MQL → SQL

**核心**：LLM 只负责"理解业务语义"，确定性引擎负责"执行翻译"。中间用一份**业务语义稿（MQL DSL）**隔开。

```
用户 NL ──[LLM 理解]──▶ MQL（纯业务语义稿）──[确定性引擎·零LLM]──▶ SQL ──[只读执行]──▶ 数据
```

### MQL 格式硬规则（防幻觉的第一道闸）
- MQL **只能含业务语义**：指标名、业务维度、时间意图、口径版本、过滤等业务语言。
- **一旦 MQL 中出现物理表名 / 字段名 → 判格式错误，直接拒绝**，退回铨度重新产出。
- JOIN 键、表、过滤列**不允许在 MQL 里出现**——它们由确定性引擎按本体 relations 生成。
- 本团映射：`IntentContract` + 铨度 `DSL JSON` 联合构成 MQL 层。既有 DSL 已含 `metric/dimensions/time/guards/ontology_refs`，符合纯业务语义要求。

### 确定性编译（本团已有，需强化约束）
`sg-dsl-compiler` 编译规则 1~7 即确定性引擎。**新增铁律**：
- 选表按「粒度覆盖 × 维度覆盖 × 预聚合 × 权威等级（金>银，废弃跳过）」，不可凭印象选。
- **JOIN 键唯一来源是本体 relations**（`thick_semantic_layer.md` 支柱1），永不猜测。
- 翻译失败如实报错，不"猜一个能跑的 SQL"。

## 二、三令牌护栏（内容指纹绑定 + 短 TTL）

令牌不是口令，而是**绑定内容指纹**的凭证：签发时绑定内容，校验时比对，换内容重放即拒。

| 令牌 | 签发时机 | 绑定内容 | 防护 |
|---|---|---|---|
| **确认令牌** | 翻译前向用户展示口径/维度/公式/数据截止时间并获确认后 | MQL 指纹 | 防跳过确认直接翻译；语义改了必须重确认 |
| **查询令牌** | 确定性翻译成功后 | SQL 原文 | 防绕过引擎裸执行任意 SQL；执行须携带且 SQL 逐字一致 |
| **探索令牌** | 探索校验通过后 | SQL 指纹 + 120s TTL | 探索与正式链物理隔离；只用于未注册指标的预览 |

**本团映射**：
- 确认令牌 → `sg-sql-materialization` Step1「用户确认门禁」+ `materialization.confirmation_required` 字段。
- 查询令牌 → 快车道执行前 `materialized_sql_guard` 校验（已实现只读头检查）+ 新增 SQL 指纹比对。
- 探索令牌 → `sg-adhoc-indicator` 即席构建，须带只读护栏 + 行数上限 + 短 TTL。

## 三、只读执行器（真实护栏，非声明）

- `FORBIDDEN` 正则拦截 `INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/TRUNCATE/MERGE` 等写操作（词边界匹配，防注释绕过）。
- 行数上限 `MAX_ROWS=1000`（本团参考：DB2 MCP 自动追加 `FETCH FIRST`；自定义 `FETCH FIRST` 会 SQLCODE=-104，故靠 MCP limit 参数）。
- 分区条件强制：大表必须带 `YMD`/分区键。
- 失败如实报错，不用降级到"能跑但不准"的裸查询。

## 四、探索取数 → 固化闭环（未注册指标也能服务）

1. 指标未注册但用户想先看数 → 走**探索分支**：独立令牌、护栏一致（只读 + 白名单 + 分区 + 行数上限）。
2. 三模式：贴 SQL / NL 起草 / 起草+精修；除自贴 SQL 外**必先确认**。
3. 探索稳定后**固化草稿**：
   - `SELECT` 聚合表达式 → 候选指标公式；
   - `GROUP BY` → 候选维度；
   - `WHERE` → 必要过滤；
   - 物理列**自动反查业务属性**（经铨度/舆图）。
4. **人工确认 → 注册本体 → 新指标立即可走标准快车道**。这正是本团 `sg-sql-materialization` 六步闭环的探索侧入口。

## 五、金标准回归 + 反馈飞轮（eval loop）

- **金标准数据集**：本团已有 `knowledge/design/eval/黄金问题集-v1.0.csv` 与 `sg-eval-harness`。要求每个语义层/规则改动后跑全量回归，防"救一个 case 打挂十个"。
- **翻译快照锁定**：每次规则变更记录 before/after，对比全量回归结果。
- **反馈三态**：用户对答案 `采纳 / 修改 / 拒绝` → 归因：
  | 用户动作 | 归因 | 改进 |
  |---|---|---|
  | 实体识别错 | 语义层缺词 | 铨度/诠枢补 glossary/synset |
  | 语义稿错 | 检索不到位 | 优化 KB 检索与 OAG 增强 |
  | 翻译错 | 编译映射错 | 淬锋修 DSL→SQL 规则 |
  | 高频模式 | 可固化 | 衍薪固化为物化 SQL / 技能 |
- **CI 门禁**：准确率下降 >2pp 无条件回退（衍薪已有该铁律，本文件再次强调适用于语义层变更）。

## 六、回答强制标注（信任最后一公里）
