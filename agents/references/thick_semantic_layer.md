# 厚语义层四支柱 + 本体五件套（源自两篇 Data Agent/语义层文章 · 2026-11-16 提炼）

> 来源：
> ①《Data Agent 深度调研报告（2026版）》https://mp.weixin.qq.com/s/o9gQkKZUuTsGLToIUlRRmA
> ②《语义层的厚度是智能问数 Text2SQL 的制胜点》https://mp.weixin.qq.com/s/Pa4fNQwog2TOfZbOKpHjfQ
> 核心共识：**准确率属于语义层，不属于 LLM**。GPT-4o 在 Spider 2.0-Snow 无语义层仅 10.1%；语义路由可降数据类错误最多 66%。
> 本文件为铨度（sg-semantic）与诠枢（sg-semantic-modeler）的能力增强规则源。

## 一、为什么"厚"才是制胜点

纯 LLM 方案为了保准确率不得不**简化语义层**（甚至只支持单表），形成死循环：语义层越简单→场景越少→越不敢投入→Demo 好真实业务废。
突破口：用**确定性编译**承担复杂度（规则驱动，配置验证一次永久正确），LLM 只做"理解业务语义"。本团已有 `sg-dsl-compiler` 确定性编译，具备承载厚语义层的前提。

## 二、厚语义层四支柱（铨度必须覆盖）

### 支柱 1 · 关联体系（语义层的骨架）
> 纯 LLM 最容易翻车的重灾区。不止主键外键配对。

| 能力 | 要求 |
|---|---|
| 主子表关系 | 显式标注 header/detail 及聚合方向 |
| 多级关联链路 | 支持 A→B→C 传递，链路在 relations 中登记 |
| 同维度跨表自动对齐 | 多事实表同属"年/月/厂别"维度时自动对齐，**用户不写 JOIN** |
| JOIN 键唯一来源 | **join_key 只能来自本体 relations，禁止 Agent 猜 JOIN**（与 `sg-dsl-compiler` 规则3 对齐） |
| 基数标注 | 每个关系标 1:1 / 1:N / N:M，防 fan-out 重复计数 |

### 支柱 2 · 维度体系（分析坐标系）
| 能力 | 要求 |
|---|---|
| 层级结构 | 年-季-月-日、省-市-区，支持上钻下取 |
| 代码↔名称映射 | 编码自动转业务可读名（如 COST_CENTER→成本中心名） |
| 计算维度 | 年龄分段、客户价值分层、工序大类等派生维度 |
| 时间口径 | 自然月 vs 财月显式区分；成本域 V1/V4/V3 期间口径锁定 |
| 粒度声明 | 每个指标的 grain 必须写明（day/factory/heat/order…） |

### 支柱 3 · 指标体系（价值核心）
| 能力 | 要求 |
|---|---|
| 复合口径 | 派生/复合指标的完整 formula，引用已注册原子 |
| 聚合前后过滤 | 明确 WHERE 在聚合前还是 HAVING 在聚合后 |
| 跨行运算 | 同比/环比/累积/占比/排名，标注窗口与分母 |
| 聚合性 | 可加/不可加/半累加（与四类计算错误防御对齐） |
| 口径族+版本 | family + version，防多版本混用 |

### 支柱 4 · 业务词典（翻译接口）
不止同义词，需覆盖**多词类**：
`实体词`（铁水/中板）、`字段词`（重量/成本）、`聚合词`（合计/平均）、`比较词`（超过/低于）、`宏词`（本月/同期）、`字段簇`（产量族）、`动词`（查/对比/归因）、`常数词`（本部/三基地）。
- 每个词条必须指向**已注册对象或指标**，禁止悬空词。
- 黑话映射：`poi→门店` 式映射，原始词→标准术语。本团对应：口语→ZB_CODE。

## 三、本体五件套（唯一事实源 · 排序交付）

| # | 文件 | 作用 | 防幻觉关键字段 |
|---|---|---|---|
| 1 | `objects` 业务对象 | 有哪些实体/属性/在哪张表/字段映射 | 域/类型/状态/敏感级；`required_filters`（如 `IS_VALID`）；物理映射 layer/authority（金>银，废弃跳过） |
| 2 | `functions` 指标口径 | 每个指标怎么算 | 公式（**仅白名单函数**）；`required_filters`；口径族 family+version；`do_not` 反面说明（"不要直接 AVG，先按订单去重"） |
| 3 | `relations` 对象关系 | 对象怎么关联 | `join_key`（**JOIN 唯一来源**）；基数 1:1/1:N/N:M |
| 4 | `glossary` 黑话词典 | 口语→标准术语 | 原始词→标准词，必须指向已注册 object/function |
| 5 | `config` 全局配置 | 时间维度/分区列叫什么 | 换主题只改这里，引擎零改动 |

**贯穿铁律**：口径、JOIN、过滤、单位**全部以本体为准，任何模块不自己发明**。换业务主题只改 5 份文件。

## 五、确定性 vs 概率的取舍

- 语义层是**规则驱动**：每个关联/维度/指标有明确定义，验证正确后永久正确。
- LLM 是**概率生成**：这次对不代表下次对。
- 因此：**宁可让确定性引擎"少答但准"，不要让 LLM"多答但飘"**——这正是 `sg-dsl-compiler` 零概率编译的价值。

## 六、边用边建（落地节奏）

数据治理不完善时不必等全公司治理完：
1. 从几个核心表 + 高频指标开始；
2. 配置一个 → 验证一个 → 上线一个；
3. 语义层越用越厚，系统越用越准；
4. 每批注册后触发 `sg-eval-harness` 回归，确认该域准确率不降（与铨度 MD §1.5 分批策略一致）。

## 七、回答强制标注四要素（文章1 的信任机制）

任何基于语义层的回答，必须标注：
**① 指标名 ② 口径版本 ③ 计算公式 ④ 数据截止时间**。
缺一视为不合格交付——与 `fast_lane_response.md` 的"口径卡五字段"和铨度"draft 标注"要求叠加执行。
