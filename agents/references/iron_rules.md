## 铁律与注意事项
1. 不自行生成 SQL（交开发）、不绕过治理护栏、不用样本臆测代替真实核验。
2. 跨域协作严格经编排器中转，成员结论为准。
3. 渐进式上下文披露：只把当前域所需语义/本体子图装上下文。
4. 通知/建任务属外部动作，执行前须向用户说明目标与内容（L3 前不得联系外部）。
5. 成本域分析前须声明口径三要素（CAL_DATE 版本 + DATE_TYPE + Y_EDITION）；未声明直接作废。
6. 无证据不传递：`evidence` 缺失或 `confidence<0.6` 退回或升级，不得直接透传。
7. 不得推翻否决票（治理安全 / 质量闸门）。
8. 设计态资产不自动覆盖：合入须经本体/语义确认 + 版本备份 + 回归评测。
9. 上下文预算护栏优先于"信息完整"：当对话接近 token 上限时，主动摘要 / 落盘 / 压缩，宁可少传原文也不溢出 11115（见「上下文预算护栏」）。
10. **SQL 执行统一走 `sg-db2-executor` 双通道技能**：优先 MCP（需内网/VPN），REST 需用户自备 `lightcodegtw-token`（已清除分享包中的凭据以通过 G5-SEC）；禁止直调 `mcp__db2__execute_sql`；禁止仅输出 SQL 文本；失败时如实告知。
11. **根因分析必须走专家团队**（2026-10-13 定稿）：涉及厂别区分/多基地/存储过程解析的根因分析，必须组队派发并激活 sg-quality（主导）+ sg-ontology（本体解析）+ sg-semantic（语义校验）+ sg-metadata（元数据导航）+ sg-supervisor（强制监察）。厂别识别由专家从存储过程 SQL 中解析得出，禁止硬编码 schema→工厂映射。编排器不得自行替代专家分析（见 Workflow B）。
12. **存储过程实时溯源**（2026-10-13 定稿）：涉及存储过程逻辑分析时，必须从 DB2 SYSCAT.ROUTINES 分段拉取最新版本；本地血缘文档仅作索引参考，不作为分析依据。
13. **根因分析数据纪律**（2026-10-15 定稿 · 最高优先级 · 不可降级 · 详见「核心能力 → 10. 根因分析数据纪律」）：禁止使用「可能」「大概」「疑似」「估计」等模糊措辞；每条结论必须精准定位到表名/字段名/时间区间的具体值；必须量化差异（实际值 vs 预期值 + 偏差率）；必须附可追溯证据链（SQL + 返回值 + 双源对拍）。证据不足时只能输出 `[证据不足]` 状态并明确缺什么，禁止编造完整结论。违反任一条的根因结论一律作废退回重做。
14. **数据埋点全链路追溯纪律**（2026-10-16 定稿 · 与第13条同级 · 详见「核心能力 → 11. 数据埋点全链路追溯纪律」）：查数据必须有明确依据，从最初数据源到数据展示链路不能断、要连续。六步标准路径顺序不可跳步：定指标→验血缘→解过程→查抽数→查过程日志→查落表。**定指标必须三级降级多源定位：①三钢指标注册表(indicator_api.json) ②T_ADS_DIM_GZ01 ③三份指标血缘文档（很多指标无ZB_CODE只存在于cpt数据集）**，全部未命中 → 触发断链兜底（`lineage_fallback.md`），`[证据不足]` 仅为兜底失败终态。三层埋点（抽数时间/过程执行日志/落表时间）缺一不可。必须组队三专家并行（同一消息内三条 `delegate_expert`：sg-semantic+sg-ontology+sg-metadata），编排器不得单人串行。产出必须为 HTML 时间线报告。
15. **技能 owner 生命周期治理**（2026-10-30 定稿 · 详见 `agents/references/skill_ownership_governance.md`）：①新技能按**使用者主责**归属（不是建设者）；②专家退役必须**同步回收**其技能 owner 并写变更记录；③专家复职必须**同步归位**。**禁止**出现"在册主责却 0 技能"或"退役却技能未转"的半成品状态。共享平台技能（分析引擎/交付技能/编排技能）owner 归平台方，不视为缺陷。每次改包后跑 `scripts/check_skill_ownership.py` 校验 C1~C5。
