#### §0.3 ECharts 图表配置模式

**数据注入模式（铁律 · 图表空白的直接根因）**：所有图表数据必须在前置 JS 数组中硬编码，ECharts 从数组中直接读取渲染。严禁 fetch/异步取数、先 setOption 空对象再填入、引用 CDN。

**⚡ 落盘前数据完备性闸门（2026-10-28 新增 · 防止企微机器人首次请求图表空白）**：
> 写入 HTML 文件前，**必须执行**以下检查，不通过则不落盘：
> 1. 逐条检查所有 JS 数据数组：`Array.isArray(data.xxx) && data.xxx.length > 0`
> 2. 每个数组至少包含**预期日期的条目数**（如 7 日趋势应有 7 个值）
> 3. 所有 `echarts.init(dom)` 的目标 DOM 节点必须在 HTML 中存在
> 4. **所有图表容器必须在 `<script>` 标签之前渲染完成**（`<div id="cA">` 等先于 `<script>`）
> 
> **失败处理**：任一步不通过 → **不落盘 HTML，改为输出文本口径卡 + 警告「图表数据未完备，请重试」**。禁止用空数据生成完整 HTML 文件（这是首次空白的直接原因：HTML 文件已保存但图表数据未填充）。

**⚡⚡ JS 语法硬校验闸门（2026-10-29 新增 · 图表全空的头号根因 · 优先级最高）**：

> **真实事故**：2026-10-28 交付的《近7日钢铁料耗铁水耗趋势_v2》报告，4 个图表**全部空白**。根因不是数据缺失、不是 CDN、不是 DOM id 不匹配，而是**业务 JS 中存在 53 处 `{ {` / `} }` 双花括号**——用 Python f-string 拼装 HTML 时，`{` 被转义成 `{ {` 且未还原，导致 `function(){ { ... } }` 这类非法语法，**整个 `<script>` 块解析失败，所有图表连带崩溃**。
>
> **该类故障的隐蔽性**：数据数组完整、容器 id 正确、`setOption` 也写了，静态检查全部「看起来正常」，只有真正跑 JS 才暴露。**数据闸门查不出这种错**。

| # | 校验项 | 命令/方法 | 判定 |
|---|---|---|---|

| **R2** | 抽屉三层**严格对应**：**第一层 T_ADS 应用展示层** → **第二层 T_DWD/T_DWS 的 CDM 层（含 tmp 临时表链，逐张可展开）** → **第三层 T_ODS 贴源数据层（必须实查的真实明细行，逐行可复核）** |
| **R3** | 下钻粒度为**单指标 · 单基地 · 单日**（例：点 10-23 本部钢铁料耗 → 该日该指标完整计算过程分层展示），不是汇总趋势 |

**四域固定**：生产管制（GZPROD）+ 成本（CBPROD）+ 存货日管控 + **标准成本 vs 实际成本对比**。

**五步不可跳**：① DB2 实取（四条取数纪律）→ ② 写外置数据集 JSON（禁止代码内嵌数字）→ ③ `--check` 跑 36 项闸门（任一失败 exit 1 且不落盘）→ ④ 渲染单文件 HTML（零外链）→ ⑤ `verify_cockpit.py` 39 项验收（含 D1~D5 下钻闸门）。

**标准成本对比模块口径（必须原样呈现）**：
- 来源 `SMBB_M_S_CB00.T_DWD_FACT_CACA_DMXCBLR_GX`，**同一张表按 `版本` 维度**取 `标准成本` / `日成本`，非跨表拼接
- 差异 = 实际 − 标准（**负=节约，正=超支**）；成本影响 = 差异 × 当日工序产量 ÷ 10000
- 可比 8 工序，**不可比项（标准版本未维护）必须单列披露，禁止按 0 处理**
- **判读红线**：单工序 |差异率| > 15% 时先疑"标准定额未重估"，不得直接认定为降本成效

**交付话术要求**：回复中必须报出 D1~D5 实测数字（如「D1: 4/4 ✅｜D2: 226/226=100% ✅｜D3: lv1/2/3/4 齐全 ✅｜D4: 最小 14 行 ✅｜D5: 差额 0 ✅」），未写视为未做。

| 步骤 | 检查项 | 判定方法 | 修复 |
