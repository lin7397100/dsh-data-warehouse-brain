# sg-agentic-decision · Agentic 判断决策

## 定位

结果产出后的**决策闸门**：决定"接下来做什么"，而不是"数据是什么"。

## 触发条件

DB2 执行返回结果后、批量报表生成后、监控任务跑完后 —— 凡是有结果需要处置的场景。

## 决策矩阵

| 判定 | 信号 | 动作 | MCP |
|---|---|---|---|
| 数据异常 | 空值 / 偏离历史基线 / 质量规则违规 / 双轮不一致 | 触发 `sg-root-cause-fullchain` 或质量告警 | — |
| 需他人知晓 | 报表产出 / 异常告警 / 诊断报告完成 | 推送给指定人群 | 通知 MCP（企微 / 邮件） |
| 需跟进处理 | 根因为数据缺陷 / 需业务排查 / 需降本动作 | 创建跟进任务并指派 | 任务 MCP |
| 正常 | 结果通过可靠性闸门且无异常 | 直接交付用户 | — |

## 判断依据（三类，缺一不可）

1. **质量专家异常检测结论**（`sg-anomaly-detect` / 对账闸门 / 质控八步结果）
2. **本体业务基线**（本体专家提供的合理区间，如高炉利用系数、焦比区间）
3. **业务规则**（成本三要素一致性、双轮产量交叉校验结果）

## 工作流程

### Step 1 · 收集判定输入

```
质量闸门结论：通过 / 拦截（失败项）
异常检测结果：{指标, 当前值, 基线值, 偏离幅度, 方向}
业务基线校验：{指标, 合理区间, 是否越界}
双轮校验：生产轮产量 vs 成本轮 C010C 实绩（一致性）
```

### Step 2 · 异常判定

| 偏离幅度 | 判定 | 动作 |
|---|---|---|
| < 5%（且在基线内） | 正常 | 交付 |
| 5% ~ 15% 或 越基线 | 关注 | 交付 + 标注提示 |
| > 15% 或 空值 / 双轮不一致 | 异常 | 根因分析 |

### Step 3 · 根因归属路由（异常时）

| 根因归属 | 通知对象 | 任务类型 |
|---|---|---|
| 生产工况 | 厂部生产调度 | 工况排查任务 |
| 采购市场 | 采购部门 | 价格跟踪任务 |
| 数据缺陷 | 数据团队 | 数据修复任务 |
| 口径歧义 | 提出人 + 语义专家 | 口径澄清任务 |

### Step 4 · 输出决策 JSON

```json
{"action": "notify", "target": "厂部生产调度",
 "payload": {"title": "吨铁成本异常预警", "summary": "。.", "link": "。."},
 "reason": "成本↑15% 且产量↓8%，判定摊薄效应主导，需生产侧确认",
 "confidence": 0.82}
```

## MCP 调用铁律

1. **MCP 只做「手」不做「脑」**：仅 DB2（只读 SQL 执行）/ 通知 / 建任务三类机械动作
2. **通知与建任务属外部动作**：执行前必须向用户说明目标与内容，未说明不执行
3. 语义解析 / DSL 编译 / 本体建模 / 根因分析一律走专家技能提示词工作流，**不通过 MCP 实现**

## 输出规范

- 决策 JSON：`{action, target, payload, reason, confidence}`
- 未触发动作时输出：`{action: "deliver", reason: "结果通过全部闸门，无异常"}`

## 注意事项

1. 置信度 < 0.6 时不做自动通知/建任务，先向用户确认。
2. 同一异常在 24 小时内不重复建任务（去重）。
3. 成本域异常必须先声明口径三要素再路由。
4. 拦截态（闸门不通过）不进 Agentic 动作，直接回退纠错。
