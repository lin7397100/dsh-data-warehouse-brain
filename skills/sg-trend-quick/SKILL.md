# sg-trend-quick · 多基地趋势快线（T2a）

## 定位

**"近 N 日 × 多基地 × 单指标趋势"的唯一执行入口。**

起因：TR-20261029-1511-001（三基地钢铁料耗 7 日趋势）走完整八步 + 6 专家 + 26 次串行探针 + 11 轮闸门，耗时 **81m51s**；而其数据本体只有 **3 码 × 7 天 = 21 行**，一条 SQL 即可取回。

本技能把这条路径压缩为：**锁码 → 一条 SQL → 一轮断言 → 趋势速览**。

## 与既有链路的关系（互斥，不可混用）

| 链路 | 收什么 | 拒什么 | 目标 |
|---|---|---|---|
| 快车道 `fast_lane_response.md` | 单日/单期纯数值，≤3 指标 | **含"趋势/分析"一律拒** | ≤30s |
| **本技能 T2a** | **多基地/多指标 × 近 N 日序列** | 含根因关键词一律拒 | **≤3min** |
| 八步主链 T2b | 根因/归因/口径争议/数据缺陷 | — | ≤12min |

判型映射：T2a ≡ `Q2-T`（L1 档）；T2b ≡ `Q3-R`（L2 档）。trace 必写 `lane: "T2a"|"T2b"`。

## 准入四条件（全满足才进，任一不满足降/升档）

| # | 条件 | 判定 |
|---|---|---|
| ① | 问法含 `趋势/走势/近N日/近7日/连日/曲线/变化轨迹` | 必需 |
| ② | **不含** `为什么/原因/异常/归因/波动分析/排查/诊断/下钻/溯源/对标排名` | 必需 |
| ③ | 指标数 ≤ 5，基地数 ≤ 4 | 必需 |
| ④ | 不要求逐炉/逐工位明细（明细属 L3 抽屉） | 必需 |

命中 ② 任一关键词 → 直接进 T2b，**禁止**先出趋势再补归因（会把 3 分钟拖成 80 分钟）。

## 执行五步（禁止展开为八步）

### Step 1 · 锁码（≤15s，零全量加载）

- 用 `sg-indicator-system/engine/lookup_indicator.py` 离线匹配，或直接 `grep` `knowledge/design/indicator/indicator_index.json`。
- **禁止**加载 `indicator_registry.json` 全量（4.68MB）。
- 同一指标存在多码时**全部取回**并标 `primary/alternate`（例：泉州钢铁料耗 6012800 与 6039000 口径不同，只取一个会得出错误结论）。

### Step 2 · 一条 SQL 取全量（核心动作）

按 `materialized_sql/<ZB_CODE>.sql` 头部的 `SOURCE_TABLES` 确定表名，再把单日单码改写为**多码区间批查**：

```sql
SELECT ZB_CODE, YMD, ZB_VALUE
FROM   SMBB_M_S_ZZ00.T_DWS_FACT_ZZGZ_LG01
WHERE  ZB_CODE IN ('1600213','5000106','6012800')
  AND  YMD BETWEEN '20261022' AND '20261028'
ORDER  BY ZB_CODE, YMD
```

铁律：

1. **一次往返拿全量**。禁止"逐基地一条、逐日一条"。3 基地 × 7 天 = 1 条 SQL、21 行。
2. 表名/码值一律取自物化 SQL 头部与注册表，**不硬编码**；示例中的表仅为当前批次实测值。
3. 需要分炉座构成时，**追加一条**按 `ZB_CODE` 展开的构成查询（同上区间），最多 2 条 SQL。
4. 派生码（分子/分母）**必须先登记**（见 `agents/references/caliber_freeze.md`），未登记不得现场构造。

### Step 3 · 一轮断言（T 组 6 条，一次跑完）

| # | 断言 | 方法 | 失败动作 |
|---|---|---|---|
| T1 | 行数完备 | `行数 = 码数 × 天数`（剔除停更码后） | block |
| T2 | 日期连续 | `YMD` 去重排序后与自然日序列逐一比对 | block |
| T3 | 主键唯一 | `ZB_CODE + YMD` 无重复 | block |
| T4 | 码值合法 | 全部 `ZB_CODE` 能在注册表命中 | block |
| T5 | 空值/零值 | NULL 率与零值率逐码统计 | flag |
| T6 | 量级合理 | 相邻日比值 ∈ [0.7, 1.4]，越界逐条列出 | flag |

> 完整 12 条断言（含口径组/一致性组）见 `agents/references/caliber_freeze.md`。T2a 只跑 T 组 6 条，**不跑** Mix/Rate 分解、不做跨基地排名。

### Step 4 · 渲染趋势速览（唯一合法输出）

```markdown
**<指标> 近7日（<起>–<止>）**：<一句话结论，含最大变化基地与幅度>

| 基地 | 7日均值 | 首日 | 末日 | Δ | 极差 | 判读 |
|---|---|---|---|---|---|---|

<趋势图：三行折线，内联 echarts，≤200KB，禁止 CDN>

**口径卡**：ZB_CODE / ZB_NAME / FACTORY_DIV / 成熟度 / 置信度（每个基地一行）

**数据限制**：停更码、恒定序列、未校准、不可跨基地排名等，逐条列；无则写「无」
```

### Step 5 · 阈值门（决定要不要升 T2b）

| 触发 | 动作 |
|---|---|
| 任一基地 绝对变化 > 3σ 或 > 2% | 在结论末尾加一行「建议归因：<基地> <指标> 变动 <x>，是否展开 T2b？」**等用户确认** |
| 未触发 | 直接交付，**禁止**主动做归因、预测、建议 |

## 硬禁令（出现任一即违规，监衡记档）

1. ❌ 出 1.1MB 级 HTML、四层抽屉下钻（属 L3）
2. ❌ 做 Mix/Rate/Cross 分解、贡献度分解、预测外推
3. ❌ 派 6 专家；T2a 最多 3 位（`sg-semantic` 锁码 / `sg-development` 执行 / `sg-quality` 断言）
4. ❌ 逐基地逐日循环取数（往返 > 2 次即违规）
5. ❌ 口径在 Step 3 之后再改（改则整体作废重跑，禁止就地补丁）

## SLA 与验收

| 指标 | 目标 | 违规线 |
|---|---|---|
| 总耗时 | **≤ 3 min** | > 5 min → 监衡告警「T2a 失效」 |
| SQL 条数 | ≤ 2 | > 2 → 违规 |
| DB2 往返 | ≤ 2 | > 3 → 违规 |
| 产物体积 | ≤ 250KB | > 500KB → 违规 |
| 断言轮次 | 1 | > 2 → 违规 |

基线对比（TR-20261029-1511-001）：82 min / 26 往返 / 1.10MB / 11 轮闸门。

## 已知陷阱（钢铁料耗族 · 2026-10-29 实测，可直接复用）

| 基地 | 码 | 陷阱 | 正确做法 |
|---|---|---|---|
| 本部 | 1600213 | 报表口径含 `-1` 修正，原始值 1055.89 vs 发布 1054.89 | 显式声明「含 -1 修正」，勿与未修正值混比 |
| 罗源 | 5000106 | 50T 码 `5000094` 自 2024-09-09 停更 | 必须标注停更，构成只用 120T(5000100)+110T(5000207) |
| 泉州 | 6012800 | 7 日极差仅 0.13，低于称量噪声 1.05 | 标 `TREND_UNRELIABLE`，禁止据此下趋势结论 |
| 三基地 | — | 三码差值仅 5.47 kg/t（0.52%），疑同源派生 | **禁止跨基地排名**，只做同向/异向陈述 |
