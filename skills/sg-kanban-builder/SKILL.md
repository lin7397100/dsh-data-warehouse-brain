# sg-kanban-builder · 交互式看板搭建

## 定位

面向"看板 / 仪表盘 / 驾驶舱 / 大盘 / 监控视图 / KPI 看板"类诉求，产出**一屏总览**的交互式看板。

> 🚨 **路由铁律**：用户消息含看板类关键词 → **必走本技能**，禁止进入 `sg-nl2sql-query`（即使同时提到表名）。

## P0 硬约束

| # | 规则 |
|---|---|
| 1 | **声明式构建**：先规划布局与组件清单，再生成，禁止边写边想 |
| 2 | **图表多样性**：≥ 5 种不同图表类型（用户明确只要某几种除外） |
| 3 | **数据保真**：能聚合不截断；要截断必配排序；时间型降粒度；分类基数爆炸换图表类型 |
| 4 | **同环比用专用组件**：不要手工拼"环比列"假装趋势对比 |
| 5 | **产物落盘固定位置**：`<workspace_folder>/artifacts/analysis/`，不写插件目录或系统临时目录 |
| 6 | **不主动发布/外发**：生成后交付用户确认，推送属外部动作需用户明确同意 |
| 7 | **取数走开发专家**：数据集 SQL 交 `sg-dsl-compiler` 编译 + 治理专家护栏后再执行 |

## 工作流（六步）

### Step 1 · 需求澄清（最少化提问）

只问会改变看板结构的信息：**主题 / 指标集 / 时间范围 / 对比维度 / 用户群**。
历史点数量、默认基期等可行性问题交给工具检查，不打断用户。

### Step 2 · 数据概览

经元数据/语义专家确认：涉及哪些表与指标、粒度、口径版本、是否需要双轮数据。
输出**数据概览表**（表 / 关键字段 / 粒度 / 数据量 / 口径版本）。

### Step 3 · 布局规划

| 区 | 内容 |
|---|---|
| 顶部 | Hero KPI 网格（4~6 个核心指标 + 迷你趋势） |
| 中部 | 主趋势图（时间序列）+ 对比图（多厂/多产线） |
| 下部 | 明细表 / 构成图（成本项、品种结构）/ 异常清单 |

输出**布局摘要**（区块 / 图表类型 / 数据来源）给用户确认。

### Step 4 · 数据集定义

每个组件定义取数 SQL（交开发专家编译）：

```json
{"slot": "kpi_iron_output", "type": "kpi",
 "sql": "SELECT SUM(ZB_VALUE) FROM … WHERE ZB_NAME='铁水产量' AND YMD='$TD$'",
 "refresh": "daily", "caliber": "V1/当日"}
```

### Step 5 · 生成看板

组装**自包含单文件 HTML**：

- CDN 图表库（显式声明依赖，如 ECharts）
- **浅色主题**（跟随 IDE 主题，文字深色，保证可读）
- **移动端适配**（栅格自适应，避免手机端图表重叠）
- 组件：KPI 卡片 / 折线 / 柱状 / 饼图 / 热力 / 表格 / 排名条

### Step 6 · 交付与确认

落盘 → 向用户呈现 → 等用户确认后再决定是否推送（通知 MCP 需用户明确同意）。

## 三钢看板模板

### 模板 A · 生产经营驾驶舱

```
KPI：铁水产量 / 钢产量 / 钢材产量 / 综合成材率 / 高炉利用系数 / 吨钢综合能耗
图：产量 30 日趋势 | 各工序产量对比 | 品种结构饼图 | 能耗热力图 | 异常清单表
```

### 模板 B · 日成本监控看板

```
KPI：吨铁成本 / 吨钢成本 / 成本偏差率 / 批处理状态 / 双轮校验状态
图：成本趋势（含预算线） | 成本中心偏差 Top10 | 成本项构成 | 量价结构分解
注：成本指标降为好，颜色语义反转
```

### 模板 C · 双轮管控看板

```
左轮：生产轮 KPI（产量/作业率/质量）
右轮：成本轮 KPI（单耗/单价/工序成本）
中：双轮联动指标（单位成本 = 成本/产量）+ 一致性校验状态
```

## 输出规范

- 自包含 HTML 文件路径（`<workspace_folder>/artifacts/analysis/`）
- 数据概览表 + 布局摘要 + 数据集清单（SQL + 口径）
- 刷新与维护说明（数据来源、口径版本、更新频率）

## 注意事项

1. **数值必须来自已核验结果**，不为美观调整数值或静默截断。
2. 缺失数据显式标注（"无数据"），不用 0 或前值填充。
3. 成本域颜色语义反转必须在图例处标注，避免误读。
4. 看板 SQL 同样要过治理专家护栏（只读 + 分区条件 + 行数上限）。
5. 生成后不自动外发 —— 推送必须用户明确同意。
