# sg-multi-agent-coordination · 多专家并行调度

## 定位

编排器的**调度内核**：谁先做、谁并行、谁等谁、结果怎么合并。

## 触发条件

单任务涉及 2 个以上专家（根因分析的并行取证、报表的批量编译、双轮管控的多专家下钻）。

## 调度模式

| 模式 | 场景 | 说明 |
|---|---|---|
| **串行链** | 智能问数主链路 | 语义 → 开发 → 治理 → 洞察，前一环产出是后一环输入 |
| **并行取证** | 根因分析五维信息 | 元数据 / 语义 / 本体同时采集，最后合并 |
| **扇出聚合** | 报表批量 KPI | 开发专家批量编译 → 批量执行 → 质量把关 → 洞察聚合渲染 |
| **条件分支** | 双轮管控 | 按联动模式路由到不同专家继续下钻 |

## 消息协议（结构化 JSON）

```json
{"msg_id": "m-001", "from": "data-warehouse-brain-team-lead", "to": "sg-semantic",
 "type": "request|response|notify",
 "intent": {"intent_type": "metric_query", "domain": "production"},
 "payload": {}, "depends_on": [], "deadline": "sync|async",
 "context_refs": {"ontology_subgraph": "轧钢", "semantic_scope": "ZG01"}}
```

**字段约定**

- `depends_on`：依赖的消息 ID 列表，未完成则等待
- `deadline`：`sync` 阻塞等待 / `async` 后台执行后回调
- `context_refs`：**只传当前域所需的上下文引用**，不传全量（渐进式上下文披露）

## 上下文管理（P0）

1. **按域裁剪**：只装入当前 `domain` 的语义层与本体子图
2. **按需展开**：先给实体与关系，需要时再展开字段清单
3. **结果摘要化**：专家间传递结果摘要 + 引用指针，不传原始大结果集
4. **上限控制**：单次上下文中的表结构 ≤ 20 张，候选指标 ≤ 30 个

## 标准编排模板

### 模板 A · 智能问数

```
编排器(意图解析) → 语义(解析+DSL) → 开发(编译) → 治理(护栏) → DB2执行
                                                      ↓
              洞察(渲染) ← 质量(可靠性闸门) ← 结果
                                                      ↓
                                        编排器(Agentic 判断 → 通知/任务/交付)
```

### 模板 B · 全链路根因分析

```
编排器(受理) ──┬→ 元数据(血缘取证)  ┐
               ├→ 语义(口径取证)    ├→ 质量(合并 → 逐层核验 → 研判)
               └→ 本体(业务取证)    ┘
```

### 模板 C · 生产报表自动汇总

```
洞察(模板加载) → 开发(批量 DSL 编译) → DB2 批量执行
      → 质量(逐指标异常标注) → 洞察(渲染) → 编排器(Agentic 推送)
```

### 模板 D · 日成本报表

```
质量(批处理健康检查) → 开发(版本化取数) → DB2 执行
      → 质量(预算对标 + 双轮产量交叉校验) → 洞察(渲染)
```

## 输出规范

- 调度计划表：阶段 / 主责专家 / 并行度 / 依赖 / 输入 / 产出
- 消息日志：`msg_id` + 发送方 + 接收方 + 时间戳 + 状态
- 汇总结论：各专家产出摘要 + 冲突项及处置

## 注意事项

1. **编排器不代成员改写结论** —— 成员结论为准，冲突时回退成员复核。
2. 并行取证时各方独立输出，不得互相引用未完成的中间结论。
3. 任一依赖失败 → 整体回退到上一阶段，不产出半成品。
4. 跨域协作严格经编排器中转，专家之间不直接互相调用。

## 与 sg-orchestrator 的关系（2026-11-06 改造落地）

本技能是**调度内核**（谁先做/并行/合并）；`sg-orchestrator` 是**控制平面**（六阶段 P0~P5 + 阶段契约 + 写者独占 + 唯一签发权 + 防过早发布/回溯）。

- 对「对标本周炼钢成本与定额标准」及一切"取数→计算→报告→治理→签发"型任务，**必须**经 `sg-orchestrator` 的 `Orchestrator` 驱动器走六阶段（见 `agents/references/orchestrator_runtime.md`）。
- `sg-orchestrator` 提供的运行时：`contract_ledger`（契约台账 + 写者令牌）、`gates`（G0~G5 + C-GOV-3/4/6 + C-G11 + C28/C29 + D1~D5）、`fast_lane`（单指标短路）、`scoped_context`（范围上下文）、`caliber_registry`（L3c 口径锁死）、`orchestrate`（六阶段驱动器）。
- 本技能的"调度模式"仍是拓扑选择依据；但**每阶段的写者独占、退出闸门、唯一签发权**由 `sg-orchestrator` 强制，本技能不重复造闸门。
