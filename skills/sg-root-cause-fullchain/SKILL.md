# sg-root-cause-fullchain · 全链路根因分析

## 定位

把"黑盒查询"变成**玻璃盒子** —— 用户不仅能看到数字，还能看到数字的每一层来源、口径、计算逻辑与本体关系。信任建立在透明之上。

## 五维信息展示（多专家并行取证）

| 维度 | 负责专家 | 展示内容 | 数据来源 |
|---|---|---|---|
| ① 数据血缘 | 元数据 | ODS→DWD→DWS→ADS 物理链路、表结构、数据量、最后更新时间 | DDL 9167 表 + 过程解析 |
| ② 语义定义 | 语义 | 指标口径（ZB_NAME/单位/厂部）、SQL1 原始配置、与近似指标区别 | `T_ADS_DIM_GZ01` 语义模型 |
| ③ 业务逻辑 | 本体 | 存储过程完整计算逻辑：CTE 步骤、DECODE 映射、聚合口径、日期参数语义 | 105 个过程解析结果 |
| ④ 本体图谱 | 本体 | 指标关联的业务实体与关系图（轧机-轧制-钢坯-班组） | 本体图谱文件 |
| ⑤ 本体建模信息 | 本体 | 完整数据本体血缘：KPI→语义→DWS→过程→ODS 逐层展开 | 本体血缘文件 |

## 五类根因

| # | 根因 | 典型证据 |
|---|---|---|
| ① | **口径歧义**（最常见） | 用户理解与指标定义不一致；近似指标混淆 |
| ② | 数据延迟 | ODS 最后更新时间 < 预期抽取时点 |
| ③ | 计算缺陷 | 存储过程逻辑边界（跨月/跨班次/NULL 处理） |
| ④ | 源数据错误 | 业务系统录入异常（ODS 原始记录即异常） |
| ⑤ | 参数错误 | 日期参数展开错误、版本参数错用 |

## 工作流（五步）

### Step 1 · 问题受理与复现

- 记录用户质疑（"这个产量数字不对"）
- **复现原查询**：锁定争议指标、时间范围、厂部、口径版本
- 确认期望值与实际值的差异（方向 + 幅度）

### Step 2 · 五维信息并行采集

编排器并行调度元数据 / 语义 / 本体专家，各自独立取证（不互相引用未完成结论）。

### Step 3 · 逐层实数据核验（DB2 MCP）

沿血缘自上而下逐层核验，每层用 SQL 抽样比对：

| 层 | 核验内容 |
|---|---|
| DWS | 结果值是否与查询一致；分组汇总是否守恒 |
| DWD | 明细汇总值是否等于 DWS 值 |
| ODS | 原始记录是否存在、是否合理、最后更新时间 |

**铁律**：必须用**真实 DB2 数据**核验，禁止用样本臆测。

### Step 3.5 · 三层埋点核验（强制前置 · 不可跳）

> 逐层数值对得上，**不代表数据"按时到齐"**。批处理晚落表、半批次、空跑覆盖，都会让"昨天的数"被读成"今天的异常"。
> 完整判定规则见 `agents/references/data_ready_gate.md`。

| 门禁 | 查什么 | 判据 |
|---|---|---|
| **G1 批处理成功性** | CREATER 同 schema `T_PUB_JOB_LOGS`（START_TIMESTAMP / IS_SUCCESSFUL / ELAPSED / PARAM_INFO / ERROR_DESC） | 末条 `IS_SUCCESSFUL='Y'`；同账期多条=重试，需看最后一次；`ELAPSED` 异常=数据量或锁等待 |
| **G2 抽数完整性** | `SMBB_M_A_CS01.V_PUB_JOB_LOGS_LD_1D_X`（`DES_OBJECT_NAME=<ODS表>`）+ ODS `REC_CREATE_TIME` MIN~MAX + 记录数 | 记录数显著低于邻日=半批次；`LAST_IN` 明显延后=抽数延迟 |
| **G3 落表时序** | DWS `LOAD_TIME` / ADS `CREATE_TIME` 的 MIN~MAX 与**查询执行时刻**比较 | 落表时间晚于查询时刻=未就绪；多段=补数或重跑，取最后一批 |

**结论必须四选一**：真异常 / 未就绪 / 半批次 / 重跑覆盖。**门禁未通过前禁止进入 Step 4 归因**——建立在未就绪数据上的归因结论一律作废。

**并行派发**：G1/G2/G3 由元数据专家（`sg-metadata`）与本体专家（`sg-ontology`）并行取证，质量专家（`sg-quality`）汇总判定，不得由单人串行代做。

### Step 4 · 大模型综合研判

输入五维证据 + 逐层核验结果 → 输出根因分类 + **置信度** + 证据链。

置信度 < 0.6 时如实说明不确定性，不下单一结论。

### Step 5 · 诊断报告 + Agentic 动作

`sg-agentic-decision` 按根因归属路由：

| 根因归属 | 通知 | 任务 |
|---|---|---|
| 生产工况 | 厂部生产调度 | 工况排查 |
| 采购市场 | 采购部门 | 价格跟踪 |
| 数据缺陷 | 数据团队 | 数据修复 |
| 口径歧义 | 提出人 + 语义专家 | 口径澄清 |

## 注意事项

1. **核验必须真实** —— 不核验就下结论是本技能最大的失职。
2. 口径歧义是最常见根因，**先查口径再查数据**（成本更低）。
3. 诊断报告必须让用户能自己复核（附 SQL 与数据来源）。
4. 根因为数据缺陷时，修复任务要写清责任方与验证方法。
