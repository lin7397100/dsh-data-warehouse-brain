# sg-skill-evolution · 技能自进化（主技能）

## 定位

专家团的**自我进化引擎**：管理技能资产生命周期，不直接服务业务查询。

## 四大模块

| 模块 | 职责 | 子技能 |
|---|---|---|
| ① 意图监控 | 识别重复任务模式 | `sg-intent` |
| ② 自动生成 | 重复任务沉淀为技能 | `sg-skill-evolution` |
| ③ 监察优化 | 反馈驱动的技能升级 | `sg-skill-evolution` |
| ④ 版本备份 | 版本管理与回滚 | `sg-skill-evolution` |

## 三条铁律

1. **自动生成的技能默认草稿态，绝不自动转正**（防错误技能污染）
2. **任何技能改动先备份后修改**（可回滚是底线）
3. **major 重构必须用户确认后才执行**

## 闭环一 · 重复任务 → 自动生成技能（省 TOKEN）

```
意图监控（识别重复模式）
   ↓ 三条件判定
TOKEN 节约评估（≥3 次回本才生成）
   ↓
提炼工作流 → 泛化参数 → 生成 SKILL.md（auto_generated: true）
   ↓
drafts/ 草稿试运行
   ↓ 观察期 3~5 次
成功率 ≥90% 且无需人工修正 → 转正 | 频繁出错 → 降级/废弃
```

## 闭环二 · 技能不完善 → 监察优化升级（保质量）

```
反馈采集（显性：用户直接指出 / 隐性：反复纠正、频繁重做）
   ↓
定位目标专家 + 技能
   ↓
缺陷诊断（缺步骤 / 规则不全 / 模板陈旧 / 触发词冲突 / 知识过期）
   ↓
备份 → 优化升级 → 版本号递进
   ↓
回归验证（历史失败案例重跑）→ 更差则回滚
```

## 闭环三 · 版本迭代管理与备份（可回滚）

```
skills/
├── .versions/{skill-name}/v{x.y.z}.md + CHANGELOG.md
├── drafts/{new-skill}/SKILL.md
└── {正式技能}.md
```

**升级标准操作（强制顺序）**：

1. **备份** → 2. **记录 CHANGELOG** → 3. **升级** → 4. **验证** → 5. **回滚预案**

## 版本规范

语义化版本 `major.minor.patch`：

| 变更 | 版本 |
|---|---|
| 修复错别字/小修 | patch |
| 新增步骤/规则 | minor |
| 工作流重构 | **major（需用户确认）** |

CHANGELOG 条目：`{时间, 触发源, 版本, 变更内容, 原因, 回归结果}`

## 触发场景

| 用户表述 | 动作 |
|---|---|
| "这个任务我经常做" / "又要做一遍" | 意图监控 + 评估生成 |
| "把这个流程固化成技能" | 直接生成草稿技能 |
| "XX 专家的技能不好用/不完善" | 监察优化闭环 |
| "这个技能改一下" | 版本化升级（先备份） |
| "回滚到上一版" | 版本回滚 |

## 输出规范

- 新技能：标准 `SKILL.md`（frontmatter + 触发词 + 工作流 + 输出规范）+ 草稿标记
- 优化报告：触发源 / 变更 / 原因 / 回归结果
- 版本记录：版本号 + CHANGELOG 条目 + 回滚路径

## 注意事项

1. **不直接回答业务查询** —— 收到业务问题交编排器路由。
2. TOKEN 节约评估保守估计，宁可不生成也不滥生成。
3. 每次变更后必须给出可回滚路径与验证方法。
4. 安全/合规类技能（治理专家名下）变更需治理专家会签。
