# sg-audit-compliance · 访问审计与合规检查

## 定位

让每一次数据访问**可追溯**，让合规检查**可执行**。

## 审计记录结构

```json
{"audit_id": "AUD-20260901-001",
 "timestamp": "2026-09-01 09:15:30",
 "subject": {"user": "lin", "agent": "sg-quality", "skill": "sg-anomaly-detect"},
 "object": {"schemas": ["SMBB_M_S_CB00"], "tables": ["CENTER_COST"], "level": "L4"},
 "operation": "SELECT",
 "scope": {"period": "2026-08-01~2026-08-31", "rows": 1240},
 "result": "pass|blocked|need_approval",
 "sql_digest": "SELECT … (摘要，不记录敏感常量)"}
```

## 审计落盘

- 位置：`<专家团目录>/logs/audit-{YYYY-MM}.jsonl`（追加写入，不覆盖）
- 敏感常量（具体单价/金额）不写入审计，只记 SQL 摘要与访问范围

## 合规检查清单（定期执行）

| # | 检查项 | 判定 | 处置 |
|---|---|---|---|
| 1 | 越权访问 | 访问了未授权 Schema / L4 数据未在白名单 | 告警 + 复核授权 |
| 2 | 高频敏感查询 | 同一主体短时多次访问 L4 数据 | 提示 + 确认用途 |
| 3 | 未审批写操作 | 存在未经确认的写操作记录 | **严重**，立即上报 |
| 4 | 拦截后重试绕过 | 同一 SQL 被拦截后变换形式重试 | **严重**，人工介入 |
| 5 | 敏感数据外发 | L4 数据经通知 MCP 外发 | **严重**，立即上报 |
| 6 | 审计完整性 | 审计日志是否有缺失/篡改 | 补齐或上报 |
| 7 | 分级未覆盖 | 存在未分级的高访问量表 | 补定级 |
| 8 | 设计态资产变更未走卡点 | 成本/指标口径、配置表被会话直接改写（未经 `sg-sql-safety-check` 卡点 + 双人复核） | **严重**，立即上报 + 回滚变更 |

## 工作流

### Step 1 · 记录（每次访问）

执行前后各记一条：请求条目 + 结果条目。

### Step 2 · 定期检查

每日/每周执行合规检查清单，输出检查结果。

### Step 3 · 异常处置

| 严重度 | 处置 |
|---|---|
| 严重 | 立即上报用户 + 停止相关操作 + 保留证据 |
| 告警 | 提示 + 复核授权/用途 |
| 提示 | 记录 + 观察 |

### Step 4 · 合规报告

输出周期报告：访问统计（按主体/对象/级别）、拦截统计、异常项与处置结果、改进建议。

## 输出规范

- 审计条目（追加写入 jsonl）
- 合规检查报告（清单 + 逐项结论 + 异常明细 + 处置建议）

## 注意事项

1. **审计日志只追加不覆盖**，保留期限按合规要求。
2. 审计本身不得泄露敏感数据（不记录明细常量）。
3. 发现"拦截后绕过"类行为必须立即上报，不自行处理。
4. 合规检查频率建议：L4 相关每日，全量每周。
