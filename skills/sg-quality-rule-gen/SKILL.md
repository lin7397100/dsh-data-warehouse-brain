# sg-quality-rule-gen · 质量规则推荐

## 定位

把"数据应该长什么样"固化为**可执行的校验规则**（SQL），从人肉检查变成机器巡检。

## 五维规则体系

| 维度 | 含义 | 典型规则 |
|---|---|---|
| **完整性** | 该有的数据有没有 | 关键字段非空、分区数据不缺、指标不缺天 |
| **唯一性** | 有没有重复 | 主键不重复、指标单表单日单值 |
| **有效性** | 值是否合法 | 枚举值合法、数值在合理区间、日期格式正确 |
| **一致性** | 跨表/跨轮是否对得上 | 双轮产量一致、父子表汇总一致、同环比勾稽 |
| **及时性** | 数据是否按时到 | ODS 抽取及时、DWS 加工及时、批处理按时完成 |

## 规则结构

```json
{"rule_id": "DQ_ZG01_001", "dimension": "完整性", "table": "SMBB_M_S_ZZ00.T_DWS_FACT_ZZGZ_ZG01",
 "name": "轧钢指标日数据完整性", "severity": "P0|P1|P2",
 "check_sql": "SELECT COUNT(DISTINCT ZB_NAME) FROM … WHERE YMD='$TD$'",
 "expect": "覆盖指标数 >= 基准值 90%", "threshold": "低于 90% 告警",
 "owner": "数据团队", "action": "通知 + 建修复任务"}
```

## 工作流（四步）

### Step 1 · 对象与维度选择

确定待治理对象（表/指标/过程）+ 关注维度（五维中选，可多选）。

### Step 2 · 规则生成

按维度套用模板 + 结合业务基线（本体专家提供的合理区间：如焦比、利用系数、作业率区间）。

**优先生成高价值规则**：

| 优先级 | 规则类型 |
|---|---|
| P0 | 双轮产量一致性、成本批处理就绪、关键指标缺数 |
| P1 | 关键字段非空、主键唯一、枚举合法 |
| P2 | 数值合理区间、同环比勾稽、及时性 |

### Step 3 · 阈值标定

- 有历史数据 → 用历史分布标定（P95 / 3σ / 业务阈值）
- 无历史数据 → 用业务基线 + 专家经验，标注"待标定"
- **不给无依据的精确阈值**

### Step 4 · 落地与巡检

- 输出校验 SQL（只读）
- 建议纳入每日自动化巡检（DSH `schedule_create` 定时任务）
- 告警路由：按 `severity` 走 Agentic 通知/建任务

## 典型规则示例

```sql
-- DQ_ZG01_001 完整性：轧钢指标日数据完整性
SELECT COUNT(DISTINCT ZB_NAME) AS 指标数
FROM SMBB_M_S_ZZ00.T_DWS_FACT_ZZGZ_ZG01
WHERE YMD = '$TD$';
-- 期望：>= 基准指标数 * 0.9

-- DQ_CB00_002 一致性：双轮产量交叉校验
SELECT (SELECT SUM(产量) FROM 成本轮C010C WHERE YMD='$TD$')
     - (SELECT SUM(产量) FROM 生产轮KPI WHERE YMD='$TD$') AS 差异量;
-- 期望：|差异量| / 生产轮产量 < 1%

-- DQ_ZG01_003 有效性：作业率合理区间
SELECT ZB_VALUE FROM … WHERE ZB_NAME='日作业率' AND YMD='$TD$';
-- 期望：0 <= 作业率 <= 100
```

## 输出规范

- 规则清单（维度 / 对象 / 规则名 / 级别 / 校验 SQL / 期望 / 阈值 / 责任方 / 处置动作）
- 阈值标定依据（历史分布 / 业务基线 / 待标定）
- 巡检建议（频率 / 时段 / 告警路由）

## 注意事项

1. 校验 SQL 必须**只读**，经治理专家护栏后执行。
2. 规则不是越多越好 —— 优先 P0/P1，避免告警疲劳。
3. 阈值无依据时标注"待标定"，不编造阈值。
4. 规则变更需版本化，变更前后告警量对比验证。
