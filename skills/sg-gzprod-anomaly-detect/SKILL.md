# sg-gzprod-anomaly-detect · 生产管制域异常自动识别

## 定位

生产管制域指标的**哨兵**：每日自动扫描六组核心指标，判定异常 → 下钻定位 → 产出诊断报告。与成本域 `sg-anomaly-detect` 形成「生产-成本」双域异常检测闭环。

**语义方向**：生产域**升为优、降为劣**（与成本域相反，渲染时务必标注方向）。

---

## 工作流（四步）

### Step 1 · 批处理就绪门禁（P0，前置 · 不走不报）

**数据没跑完，一切分析都是空中楼阁。**

| 检查项 | 方法 | 不通过处置 |
|--------|------|-----------|
| 铁前链批处理完成 | 查铁区 DWS 过程当日执行记录（`SMBB_M_S_GZ01` schema 日志） | 标注"铁前数据未就绪" |
| 炼钢链批处理完成 | 查炼钢 DWS 过程当日执行记录 | 标注"炼钢数据未就绪" |
| 轧钢链批处理完成 | 查轧钢 DWS 过程当日执行记录 | 标注"轧钢数据未就绪" |
| ZZGZ 管制报表生成 | 查 `ZZGZ` 相关过程当日 YMD 有数据 | 标注"管制报表未生成" |

> 门禁判断优先级：查 `sg-gzprod-warehouse` 域知识的 `procs[]` 列表，取生产域核心过程（`P_DWS_FACT_ZZGZ_*` 系列），查其同 schema 的 `T_PUB_JOB_LOGS` 表当日 `IS_SUCCESSFUL='Y'` 记录。
> 门禁不通过时**不产出异常结论**，只产出「数据未就绪报告」并标注缺链位置。

### Step 2 · 多维度异常判定（五类检测 × 六组指标）

#### 2.1 五类检测方法

| 方法 | 适用场景 | 判定规则 |
|------|---------|---------|
| **① 同环比** | 有稳定周期的指标 | 环比偏离 > 5% 关注(C级)；> 15% 异常(B级) |
| **② 历史基线3σ** | 波动规律的指标 | 取最近 30 日滚动窗口 μ±3σ；超出 P5~P95 区间 = 异常 |
| **③ 业务合理区间** | 有明确物理/工艺边界的指标 | 超出工艺硬边界（如作业率 > 100%、燃料比 > 600 或 < 480）→ A级 |
| **④ 固定阈值** | 管理定线的指标 | 计划完成率 < 95% → B级；库存 > 安全上限 120% → B级 |
| **⑤ 跨基地对标** | 三基地可比的指标 | 同口径不同基地偏差 > 10% 关注(C)；> 20% 异常(B) |

> 多方法并行触发时取**最严格**判定级别，并记录各方法独立结论。A/B 级自动触发 Step 3 根因下钻。

#### 2.3 严重度分级

| 级别 | 条件 | 处置 |
|------|------|------|
| **A 级** | 两条以上检测同时告警；或关键指标（铁水产量/钢产量/铁水耗）偏差 > 15%；或作业率 > 100% / 合格率 < 85% | **触发全链路根因**（Step 3） → HTML 报告（Step 4） → 企微推送 |
| **B 级** | 单项偏差 > 15%；或跨基地对标 > 20%；或固定阈值触发 | **触发全链路根因** → HTML 报告 → 企微推送 |
| **C 级** | 单项偏差 5-15%；或跨基地对标 10-20% | 口径卡摘要（Markdown） |
| **D 级** | 关注级偏差 3-5% | 仅日志记录。连续 3 日 D 级未消退 → 升级为 C 级 |

### Step 3 · 异常根因下钻（A/B 级触发 · Workflow B 强制团队协作）

> **⚡ 自动触发铁律（一票否决编排器偷懒）**：
> 
> Step 2 检出 **任何一条 A 级或 B 级异常** → 编排器**必须在同一轮对话内立即组队派发五专家（同一消息内 5 条 `delegate_expert`）**，
> **不得停在"初步分析"或"可能方向"阶段交付**。以 `confidence < 0.6` 或 `[证据不足]` 结尾的

> 
> **违例判定**：如果编排器在 A/B 级异常检出后，仅输出"可能原因/概率排序/需进一步查证"等

> 
> **编排器自检清单**（A/B 级异常检出后必须逐条确认，缺一不得结束）：
> - [ ] 五条 `delegate_expert` 是否已发起？
> - [ ] `todo_write` 是否已建五张卡（0.5a/0.5b/砺真/鼎元/舆图）并逐项推进？（铁律 A：台账 + 面板双轨）
> - [ ] sg-quality（砺真）是否已主持全链路取证？
> - [ ] sg-ontology（鼎元）是否已拉取 CREATER 过程源码？
> - [ ] sg-semantic（铨度）是否已输出口径卡（ZB_CODE + FACTORY_DIV + SQL1完整版）？
> - [ ] sg-metadata（舆图）是否已完成三层埋点取证？
> - [ ] sg-supervisor（监衡）是否已发出监察结论？
> - [ ] 最终 confidence 是否 ≥ 0.6？若 < 0.6 → 必须标注哪些证据缺失、去哪里补

A/B 级异常 → 编排器 **组队四专家并行取证 + 监衡强制监察**（建卡：`todo_write` 四张；派发：同一消息内四条 `delegate_expert`；走 team-lead.md §11 定义的六步标准路径），不可编排器自行替代：

| 专家 | 角色 | GZPROD 专属职责 |
|------|------|----------------|
| **sg-quality**（砺真） | 根因主导 | 主持全链路、双路复算、输出定量结论与置信度 |
| **sg-ontology**（鼎元） | 本体解析 | 拉 CREATER 存储过程解析计算逻辑、过滤条件、特殊处理 |
| **sg-semantic**（铨度） | 语义校验 | 查 T_ADS_DIM_GZ01 取 ZB_CODE 口径卡，确认 FACTORY_DIV/基地范围 |
| **sg-metadata**（舆图） | 元数据导航 | 检索 ODS 表结构、查三层埋点（抽数/过程日志/落表时间） |
| **sg-supervisor**（监衡） | 强制监察 | 重点监控跨基地污染、厂别混淆，异常即 escalation |

#### 3.1 GZPROD 异常根因下钻路径表

| 异常现象 | 首查证据链 | 典型根因方向 |
|----------|-----------|-------------|
| 铁水产量骤降 | ODS 铁区数据 → 高炉休风日志 → 原料投料记录 | 高炉休风/原料到货延迟/烧结配比波动 |
| 钢产量异常 | ODS 炼钢数据 → 连铸浇次记录 → 铁水供应 | 铁水不足/连铸断浇/钢种切换 |
| 燃料比飙升 | ODS 高炉操作 → 煤粉喷吹量 → 焦炭质量 | 焦炭水份高/喷煤不畅/风温偏低 |
| 铁水耗突升 | ODS 铁水计量(TMMSM21) → 炼钢配料 → 废钢比 | 废钢比下降/铁水渣量大/兑铁量异常 |
| 成材率下降 | ODS 轧钢数据 → 切头尾记录 → 废次品量 | 切头尾过多/表面缺陷/坯料尺寸偏差 |
| 机组作业率低 | 设备停机记录 → 检修日志 → ODS 时序 | 计划检修/非计划停机/交接班等待 |
| 跨基地对标异常 | 两基地同日同口径独立取数对比 | 单基地口径限定差异/合计码翻倍/炉座归属混淆 |

#### 3.2 根因纪律（继承 team-lead.md §10 · 不可降级）

- **禁止模糊措辞**：`可能/大概/疑似/估计/推测` 一律禁止
- **精准定位**：每条结论 → 具体 `SCHEMA.TABLE.COLUMN` + 时间区间（精确到日）
- **差异量化**：`实际值=X vs 基准=Y → 偏差=|X-Y| → 偏差率=W%`
- **三层埋点**：抽数时间 + 过程执行日志 + 落表时间，缺一不可
- **证据不足**：输出 `[证据不足]` + 已查来源 + 缺失证据清单，禁止编造
- **基地严格区分**：先查 T_ADS_DIM_GZ01 取 SQL1 确认范围限定（PROD_UNIT_CODE/ZB_CODE），杜绝跨基地污染

## 注意事项

1. **就绪门禁不可跳过**——数据未就绪时出异常结论是重大事故源。
2. **语义方向**：生产域「升 = 优、降 = 劣」，渲染时必须标注方向箭头和颜色（中国股市惯例：升=红、降=绿）。
3. **基地严格区分**：三基地独立判定，先查 `T_ADS_DIM_GZ01` 取 FACTORY_DIV + SQL1 确认范围限定。`T_DWS_FACT_ZZGZ_0001` 等事实表存全集团数据，不加 PROD_UNIT_CODE/ZB_CODE 过滤必跨基地混数。
4. **合计码陷阱**：BF10=本部合计（BF11+BF12+BF16）、BF20=泉州合计（BF23+BF24+BF25）。汇总前验证合计码语义——合计码与分炉一起 SUM 会翻倍。
5. **`T_DWS_FACT_ZZGZ_*` 系列末次装载 2025-06-30**（已停更），指向该系列查当期为空须判为停更而非数据缺失。
6. **D 级累积升级**：D 级项连续 3 日未消退 → 自动升级 C 级，纳入次日报告。
7. 异常判定阈值可按产线调整，但调整需记录并在报告中说明。
