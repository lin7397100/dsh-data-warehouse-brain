# sg-calc-error-guard · 四类计算错误防御

## 定位

智能问数的**正确性护栏**。AI 算错不会报错（误差可高达 +161%），必须在解析期打标、在核验期拦截。

## 四类错误与防御

### ① 重复计数（最隐蔽）

**表现**：明细被多表 JOIN 放大，聚合结果虚高。

**检测**：
- 事实表与维表一对多 JOIN 后直接 SUM
- 同一主键在多表中重复出现
- 结果行数 > 源表明细行数

**防御**：
```sql
-- 先去重到主键粒度再聚合
WITH dedup AS (SELECT DISTINCT 主键, 度量 FROM 明细)
SELECT SUM(度量) FROM dedup;
```
DSL 标记：`"dedup_required": true`

### ② 比率不可加

**表现**：合格率、单耗、单位成本跨维度直接 SUM。

**防御**：还原分子分母，各自聚合后相除（详见 `sg-semantic-layer`）。
DSL 标记：`"ratio_not_additive": true`

### ③ 半累加（跨时间陷阱）

**表现**：库存、在制、期末余额类指标跨时间累加 —— "月末库存"SUM 成"年库存"毫无意义。

**检测**：`additivity = semi_additive` 的指标遇到跨时间 SUM。

**防御**：
- 时间维度上取**期末快照**（最后一天的值）而非累加
- 或明确告知用户"该指标不可跨时间累加"，提供按期初/期末/平均三种口径供选

DSL 标记：`"semi_additive": true` + `"time_agg": "last|avg|none"`

### ④ 口径漂移

**表现**：同一指标多版本混用（v1/v2、成本 V1/V5/V7/V9、预算版本 Y_EDITION 不同），导致前后数据对不上。

**防御**：
- 强制带版本号查询，未指定时取当前生效版并**在输出中显式标注**
- 报表跨期对比时校验版本一致性，不一致则告警
- 成本域三要素（CAL_DATE 版本 / DATE_TYPE / Y_EDITION）必须同时声明

## 工作流

### Step 1 · 解析期打标

语义解析产出 DSL 时，逐项检查四类风险并写入 `guards`。

### Step 2 · 编译期约束

开发专家按 `guards` 生成 SQL（`sg-dsl-compiler`），不得忽略标记。

### Step 3 · 核验期拦截（配合质量专家）

| 核验 | 方法 |
|---|---|
| 重复计数 | 结果行数与源表 DISTINCT 主键数比对 |
| 比率 | 抽查一条：分子/分母重算是否等于结果 |
| 半累加 | 检查时间聚合方式是否与 `time_agg` 一致 |
| 口径漂移 | 校验版本字段是否与声明一致 |

### Step 4 · 输出防御报告

```json
{"guards": {"dedup_required": true, "ratio_not_additive": false,
            "semi_additive": true, "version_locked": "v1"},
 "checks": [{"item": "重复计数", "result": "pass", "evidence": "结果行数 30 = DISTINCT 主键数 30"}],
 "blocked": false}
```

## 一次过闸门（2026-10-30 新增 · 与 12 条断言矩阵配套）

> 完整矩阵见 `agents/references/caliber_freeze.md` §三。本节只写执行纪律。

TR-20261029-1511-001 复盘：闸门被当成"发现错误的工具"，逐条串行跑了 11 轮、产出 14 个闸门脚本。正确用法是**一次跑完、一次回修、二次作废**：

| 规则 | 内容 |
|---|---|
| R1 | 12 条断言**一次性全部执行**，输出 PASS/FAIL/BLOCK 矩阵，禁止"发现一条修一条" |
| R2 | 回修配额 = **1 轮**；第二轮仍 FAIL → 任务作废，退回 L3 人工 |
| R3 | A 组（结构）任一 BLOCK → 禁止进入归因与报告，只能退回取数 |
| R4 | flag 项不阻断交付，但必须逐条写入结论「数据限制」段，缺一即质量违规 |
| R5 | 矩阵结果写 trace `assertion_matrix`，监衡按 `rounds > 2` 判违规 |

> 判据：T2a 只跑 7 条（A1–A4 + C1–C3），T2b 跑全 12 条。**闸门不是越多越好，是一次到位。**

## 与质量专家的分工

| 阶段 | 本技能（语义侧） | 质量专家（结果侧） |
|---|---|---|
| 时机 | 解析期（生成 SQL 前） | 核验期（执行后） |
| 手段 | 规则打标 + 约束编译 | 对账闸门 + 独立质控八步 |
| 产出 | `guards` 标记 | 拦截 / 放行结论 |

## 输出规范

- **解析期**：DSL 中的 `guards` 对象（四类标记 + 版本锁定）+ 打标依据说明
- **核验期**：防御报告 JSON —— `guards` + `checks`（逐项检查项 / 结果 / 证据）+ `blocked` 标记
- **拦截时**：明确说明是哪类错误、证据是什么、如何修正（不给模糊的"可能有问题"）

## 注意事项

1. 打标**不影响性能**，只影响编译方式 —— 不要为了"看起来没问题"而省略标记。
2. 半累加指标在用户未指定口径时，默认取**期末值**并明确告知。
3. 版本不一致导致的差异不是"数据错误"，但必须在结论中说明，避免误判为异常。
