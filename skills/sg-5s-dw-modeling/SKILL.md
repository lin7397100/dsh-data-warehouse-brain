### 0.0 5S平台标准建数流程（来自三份权威资料，必须严格遵循）
> 以下流程严格依据三份资料对齐：①《数字工匠实操题0928选拔赛》"大数据全流程开发"标准操作步骤；②《XDATA-数成用户手册2024Q3》BEDF52/BEDF54/BEDK01-04 页面机制；③《5S平台数据模型开发规范》ODS→CDM(DWD/DWS)→ADS 数据分层与加工流程。生成指南的页面号、命名后缀、建数顺序必须与此一致，不可凭空编写。

- **操作平台**：`http://test.eplat.fjsg.com/eplat/web/BE00#`
- **真实页面号**（平台操作）：
  - 业务指标登记：平台首页 → 研发 → 治理 → 规划 → 业务指标（需审批）
  - 维度/事实模型：规范指标建模 **BEDF52**；维度管理/物化 **BEDK01**；表物化审批 **BEDP1004**
  - 原子/派生/复合指标：技术指标模型 **BEDF54**；指标生成/派生指标生成 **BEDK02**；指标汇总（生成DWS汇总表）**BEDK03**
  - 任务编排 **BEDD00**；任务编排审批 **BEDD0002**；数据API上线 **BEDR17**
- **命名后缀规则**：中文资产名与英文资产名均在题名后加后缀 **`_账号后两位数字编码`**（如账号 SZGJ01 → `_01`）；0928选拔赛中文用 `_姓名`（如 `_张小小`），英文用 `_01`。指南范例统一用 `_01` 演示，便于区分不同开发者的资产。
- **标准建数操作流程**（顺序即指南步骤顺序，完全对齐三份资料）：
  1. **业务指标登记**（BEDF54/首页业务指标菜单）→ 审批
  2. **维度模型创建 + 物化**（BEDF52 建 DIM_ → BEDK01 生成数据表 → 物化审批 BEDP1004）
  3. **事实明细模型创建 + 关联维度字段 + 物化**（BEDF52 建 FACT_ → "关联维度"选步骤2已物化的维度表 → BEDK01 生成数据表 → 物化审批 BEDP1004）
  4. **原子指标**（BEDF54，必须关联步骤3的事实明细模型、选择数据域、表达式如 SUM(重量)，字段来自事实模型）
  5. **派生指标**（BEDK02，必须关联：原子指标 + 业务指标 + 选数据类型；统计维度 = 维度表中被关联的维度字段（主键或候选键）；通用限定 = DWS 表数据加工时的 WHERE 条件）
  6. **派生指标生成**（BEDK02 "生成" → 物化业务指标）
  7. **自动汇总指标**（BEDK03 指标汇总 → 按统计维度生成 DWS 汇总表 T_DWS_FACT_… → 物化审批 BEDP1004）
  8. **生成步骤（自动生成数据加工步骤）**：平台依据 事实模型映射(ODS→DWD) 与 汇总表(统计维度=GROUP BY、通用限定=WHERE) 自动生成数据加工步骤（BEDD02）——ODS→DWD 事实表加工、DWS 汇总加工
  9. **任务编排**（BEDD00 编排上述步骤 → 设调度如每天7:00 → 审批上线 BEDD0002）
  10. **数据服务单元 + 数据API**（M_ 单物理表 / D_A_ 单表 API；需上线走 BEDR17）
  > ⚠️ **顺序铁律**：维度模型必须先于事实明细模型并完成物化（事实模型"关联维度"只能选**已物化**的维度表，手册 p86）；事实明细模型必须先于原子指标（原子指标只可基于事实明细表，手册 p38）。**数据起点在 ODS**——事实明细表(DWD)必须经"数据加工"从 ODS 清洗/转换/关联后落库，禁止把 ODS 直接当事实明细表绑定原子指标。维度建模统一采用标准星型方案（1张事实明细表 + 维度表），不提供选项式决策，直接给出最终最优结果（见本文 1.4 节）。

### 0.5 指标类型三阶判定流程（2026-10-26 新增 · 铁律级别 · 禁止凭经验猜测）

> 依据《5S平台数据模型开发规范》第五章，5S平台将指标分为三阶：原子指标 → 派生指标 → 复合指标。**收到任何建数请求后，必须先按以下流程判定指标类型，再进入对应开发指导。**

#### 0.5.1 三阶指标定义与判定标准

| 阶 | 类型 | 定义 | 判定标准 | 5S平台来源 |
|---|------|------|---------|-----------|
| **一阶** | **原子指标** | 基于单一事实明细模型的度量值表达式 | 该指标是否可以表述为**单表、单字段、单聚合函数**？（如 `SUM(重量)` / `COUNT(合同)`） | 规范 §5③：表达式=函数(字段)，字段来自事实模型 |
| **二阶** | **派生指标** | 原子指标 + 统计维度 + 时间限定 + 通用限定 | 该指标是否等于一个原子指标，但加了**统计周期（日/月/年）或业务筛选条件**？ | 规范 §5④：派生=原子+统计维度+时间限定+通用限定 |
| **三阶** | **复合指标** | 多个派生指标通过加减乘除叠加计算 | 该指标的计算公式是否可以写成**两个或以上派生指标的算术表达式**？ | 规范 §5⑤：复合=多派生指标叠加 |

#### 0.5.2 四步判定工作流（每步必执行，禁止跳步）

```
Step 1【复合判定 · 最高优先级】
  提问：该指标的计算公式是否可以写成两个或以上独立指标的加减乘除表达式？
  ├─ YES → 确定为复合指标 → 进入 Step 4，按复合指标流程指导
  │         同时列出：计算公式 + 所有依赖的派生指标清单
  └─ NO  → 进入 Step 2

Step 2【派生判定】
  提问：该指标是否基于原子指标，附加了统计周期（日/月/年）或业务限定条件？
  ├─ YES → 确定为派生指标 → 进入 Step 3
  └─ NO  → 确定为原子指标 → 直接按原子指标流程指导

Step 3【派生指标指导】
  ① 先指导底层原子指标的开发（关联事实模型 + 表达式）
  ② 再指导派生指标在 BEDK02 中的配置（原子+统计维度+时间限定+通用限定）
  ③ 最后指导派生指标生成（BEDK02）→ 自动汇总（BEDK03）

Step 4【复合指标指导】
  ① 列出所有依赖的派生指标清单（每个派生指标 = 哪个原子 + 什么统计维度）
  ② 逐一指导每个底层派生指标完成开发（按 Step 3 流程 × N 遍）
  ③ 所有派生指标物化后，在 BEDF54"复合指标模型"页签创建复合指标
  ④ 复合指标命名 IND_一级二级_自定义，表达式写加减乘除公式
  ⑤ 复合指标生成 + 物化（BEDK02）
```

### 1.3 维度建模三种维度类型（核心概念）
| 维度类型 | 定义 | 物化规则 |
|---|---|---|
| **普通维度** | 描述业务实体/事实的标准维度（日期、地点、产品、客户等），需清洗转换保证一致性 | 正常物化：生成数据表→上线申请 |
| **退化维度** | 无实际维度表关联，直接作为事实表属性的维度（事务号、订单号、发票号等），唯一标识可从事实表直接获取 | **不需要生成数据表/视图/关联数据表**；事实模型关联退化维度时可不关联维度表直接物化。⚠️复合指标不支持用不同事实表的派生指标对退化维度做关联计算 |
| **枚举维度** | 只有少量可能取值的分类/分组属性（性别、状态、类别等），取值固定 | 以枚举方式存储，不用大维度表维护，减小存储开销、提高查询效率 |

### 1.4 标准建模方案（星型，直接采用 — 不提供选项式决策）

> 依据《5S平台数据模型开发规范》与手册维度类型定义（普通/退化/枚举，p9），本部钢铁料耗类指标**统一采用标准星型建模**：1 张事实明细表（FACT_）+ 若干维度表（DIM_）。维度表由 BEDK01 物化；事实明细表在 BEDF52「关联维度」中引用已物化的维度表；退化维度（事务号/订单号等）不建维度表、直接作为事实表属性。下方给出本案例（库 SCHEMA = SMBB_M_S_ZZ00）**最终采用的真实表结构**，可直接落地，无需再判断选型。

**命名与字段铁律（DB2）**：维度表与事实明细表均带默认分区键 `REC_ID`（第1列、非空、分区=是、长度32，用 HEX(RAND()) 生成）；**统计维度字段（如 DATE_CODE / FACTORY_DIV）必须设为维度表主键**（候选键可多个）；事实明细表主键 = REC_ID，外键为统计维度字段、指向维度表主键；所有字段类型为 DB2 合法标识符（业务中文名用 COMMENT ON COLUMN 或平台字段注释维护），与 ODS 同名字段保持类型一致并标注映射。

**1.4.1 建表结构示例（以「本部钢铁料耗」为例，库 SCHEMA = SMBB_M_S_ZZ00）**

> 命名规则：`DIM_` 维度表、`FACT_` 事实明细表、`T_DWD_` 明细、`T_DWS_` 汇总、`_KB` 宽表；维度表与明细/汇总表均带默认分区键 `REC_ID`；统计维度字段必须设为维度表主键；事实明细表主键为 REC_ID。所有字段类型遵循 DB2 语法，与 ODS 同名字段保持类型一致并标注映射。示例均采用 DB2 语法。

**（1）星型 · 维度表（普通维度，BEDK01 物化；维度模型与事实模型分两次独立创建）**

```sql
-- 日期维度：统计维度字段 DATE_CODE 作主键，REC_ID 为默认分区键
CREATE TABLE SMBB_M_S_ZZ00.DIM_ZZGZ_TIME_01 (
  REC_ID      VARCHAR(32),              -- 默认分区键（HEX(RAND())）
  DATE_CODE   VARCHAR(8)   NOT NULL,    -- 日期键 YYYYMMDD，统计维度，主键
  YEAR_CODE   VARCHAR(4),               -- 年（候选键，由 DATE_CODE 派生）
  MONTH_CODE  VARCHAR(2),               -- 月（候选键，由 DATE_CODE 派生）
  DAY_CODE    VARCHAR(2),               -- 日（候选键，由 DATE_CODE 派生）
  DATE_CNAME  VARCHAR(20),              -- 中文日期（候选键）
  WEEK_CODE   VARCHAR(1),               -- 星期
  IS_WORKDAY  VARCHAR(1)                -- 是否工作日 0/1
);
-- 主键：DATE_CODE；分区键：REC_ID

-- 厂别维度：统计维度字段 FACTORY_DIV 作主键，REC_ID 为默认分区键
CREATE TABLE SMBB_M_S_ZZ00.DIM_ZZGZ_FACTORY_01 (
  REC_ID         VARCHAR(32),              -- 默认分区键（HEX(RAND())）
  FACTORY_DIV    VARCHAR(4)   NOT NULL,    -- 厂别代码 11/12/1A，统计维度，主键
  FACTORY_CNAME  VARCHAR(40),              -- 厂别中文（候选键）
  COMPANY_CODE   VARCHAR(4),               -- 所属公司（候选键）
  FACTORY_TYPE   VARCHAR(10)               -- 炼钢/轧钢
);
-- 主键：FACTORY_DIV；分区键：REC_ID
-- ODS 映射：FACTORY_DIV ← T_ODS_TMMSM21.FACTORY_DIV / T_ODS_TMMSM01.FACTORY_DIV / T_ODS_TMMSM2A.FACTORY_DIV
--          FACTORY_CNAME ← CASE 解码（P_DWS_FACT_ZZGZ_0003 行193-197）或 ODS 组织机构主数据
```

**（2）星型 · 事实明细表（DWD，由数据加工从 ODS 清洗后落库，BEDF52 物化）**

```sql
-- 字段名为 DB2 合法标识符；业务中文名通过 COMMENT ON COLUMN 或 5S 平台字段注释维护
CREATE TABLE SMBB_M_S_ZZ00.FACT_ZZGZ_GT_LH_01 (
  REC_ID              CHAR(32),          -- 主键 / 默认分区键 HEX(RAND())
  LOADER              VARCHAR(100),      -- 过程名（分区.表名）
  LOAD_TIME           VARCHAR(14),       -- 装载时间戳 YYYYMMDDHH24MISS
  AFFILIATION_DATE    VARCHAR(8),        -- 统计日期（候选键；← ODS 各表日期字段）
  FACTORY_DIV         VARCHAR(4),        -- 厂别，外键→DIM_ZZGZ_FACTORY_01（候选键；← ODS.FACTORY_DIV）
  MOLTIRON_WT         DECIMAL(18,4),     -- 铁水用量 ← SUM(T_ODS_TMMSM21.MOLTIRON_WT)
  IRON_LOSS_WT        DECIMAL(18,4),     -- 亏损量 ← SUM(T_ODS_TMMSM11B.IRON_WT_WORK_HAND+DUT_IRON_IN−DUT_IRON_OUT−IRON_WT_WORK_HAND_OFF)
  MINE_SCRAP_WT       DECIMAL(18,4),     -- 矿山废钢 ← SUM(T_ODS_TMMSM2A.DEVO_WT) WHERE MAT_CODE='A1200075'
  MINE_PIGIRON_WT     DECIMAL(18,4),     -- 矿山生铁 ← SUM(T_ODS_TMMSM2A.DEVO_WT) WHERE MAT_CODE='A0000034'
  DIRECT_SCRAP_WT     DECIMAL(18,4),     -- 直供废钢 ← SUM(T_ODS_TMMSM2A.DEVO_WT) WHERE MAT_CODE='A1100194'
  DIRECT_PIGIRON_WT   DECIMAL(18,4),     -- 直供生铁 ← SUM(T_ODS_TMMSM2A.DEVO_WT) WHERE MAT_CODE='A1100198'
  OUT_SCRAP_WT        DECIMAL(18,4),     -- 外购废钢 ← SUM(T_ODS_TMMSM2A.DEVO_WT) WHERE MAT_CODE='A1100283'
  CRUSH_SCRAP_WT      DECIMAL(18,4),     -- 转炉破碎废钢亏损维护量 ← SUM(T_ODS_TMMSM2A.DEVO_WT) WHERE MAT_CODE='A1100146'
  STEEL_PROD_WT       DECIMAL(18,4)      -- 钢坯产量 ← SUM(T_ODS_TMMSM01.MAT_WT) WHERE COMPLEX_DECIDE_CODE NOT IN ('2','4')

-- 主键：REC_ID；分区键：REC_ID；候选键：(AFFILIATION_DATE, FACTORY_DIV)
-- 事实模型「关联维度」：FACTORY_DIV→DIM_ZZGZ_FACTORY_01；AFFILIATION_DATE/DATE_CODE→DIM_ZZGZ_TIME_01
```

## 二、指标体系概念模型（必须背下来的公式）

```
业务指标（IND_…）：业务口径的顶层定义，需审批后使用
    │
原子指标：基于【事实模型】的统计逻辑抽象，表达式 = 函数(字段)，如 SUM(合同金额)
    │
派生指标 = 原子指标 + 统计维度 + 时间限定 + 通用限定
    │   · 统计维度：GROUP BY 视角（支撑汇聚/钻取/切片）；**在5S中=事实明细模型所关联维度表中的维度字段，即维度表的【主键或候选键】**（如厂别 FACTORY_DIV、日期 DATE_CODE）；只有统计维度完全相同的指标才能进同一张 DWS 汇总表
    │   · 时间限定：时间条件标准化定义（日/月/年/$TD$ 当日）
    │   · 通用限定：业务范围筛选，**即 DWS 表数据加工时的 WHERE 条件（不含时间区间）**（如 MAT_CODE='A1200075'；无则留空）
    │   · 指标类型：过程指标（中间量，不关联业务指标）/ 非过程指标（关联业务指标）
    │   · 指标状态机：未生成 → 已生成 → 已物化（汇总表存在加工任务和上游血缘）→ 已上线（周期任务上线）
    │
复合指标：一个或多个派生指标叠加计算，维度/口径继承于派生指标
    ⚠️ 不能脱离派生指标、维度和口径产生新的维度和口径
```

## 三、全流程操作指南（严格按三份资料的标准建数流程）

> 本流程严格对齐三份资料：①《数字工匠实操题0928选拔赛》"大数据全流程开发"10步；②《XDATA-数成用户手册2024Q3》BEDF52/BEDF54/BEDK01-04；③《5S平台数据模型开发规范》第2-12章（业务指标→业务过程→维度/事实模型→原子/派生/复合指标→物化→指标汇总→表管理→数据加工→任务管理→API）与 ODS→CDM(DWD/DWS)→ADS 数据分层。

### 数据分层与加工流向（一切加工起点在 ODS）
业务系统数据源(MES/产销/铁区/物流/计量检化验/销售/采购/成本…)
  → ① ETL抽数(KETTLE每日零点入 ODS，表管理"登记表"登记 T_ODS_源表，ODS不建模型)
ODS 源数据层：原始数据存放地，**一切数据加工的起点**
  → ② 数据加工(清洗/转换/关联) 落 DWD（事实明细表）
CDM 公共数据层：
  ├─ DWD 明细事实表：维度/事实模型物化而来（FACT_ / DIM_）
  └─ DWS 汇总表：指标汇总(BEDK03)按"统计维度"GROUP BY 生成（T_DWS_FACT_…）
  → ③ 指标汇总
ADS 应用数据层（T_ADS_SRV_…）→ API 数据服务（服务单元 M_ + API D_A_）

### 步骤 1 业务指标登记（首页业务指标菜单 → 审批）
1. 数据中台首页 → 研发 → 治理 → 规划 → 业务指标 → 新增
2. 选数据分类 → 命名 `IND_一级二级_指标自定义命名`（范例 `IND_ZZGZ_GT_LH_01`，加后缀 `_01`）
3. 填：业务描述、**计算逻辑**（业务语言）、**统计口径**（按哪些维度统计）、**指标单位**、**小数位数**
4. 勾选 → 提交审批（业务指标审批），管理人员审核通过后方可被派生指标关联

### 步骤 2 维度模型创建 + 物化（BEDF52 → BEDK01 → BEDP1004）
1. CDM工作空间 → 维度/事实模型 → 维度模型页签 → 新增
2. 命名 `DIM_一级二级_维度名`（范例 `DIM_ZZGZ_TIME_01` 日期维度、`DIM_ZZGZ_FACTORY_01` 厂别维度）
3. 字段第1列 `REC_ID`（主键/分区=是/长度32/非空）；选**维度类型**（普通/退化/枚举）
4. 关联工作空间 → BEDK01 维度管理 → 勾选模型 → 生成数据表（确认表英文名 `T_DWD_` 前缀、逻辑分区）→ 物化表 → 上线申请 → 审批 **BEDP1004**
> ⚠️ 维度表必须先于事实模型物化：事实模型"关联维度"只能选**已物化**的维度表（手册p86、开发规范4.2⑦）。退化维度不生成数据表。

### 步骤 3 事实明细模型创建 + 关联维度字段 + 物化（BEDF52 → BEDK01 → BEDP1004）
1. 维度/事实模型 → 事实模型页签 → 选业务过程（业务过程可在"业务过程管理"先建并审批，范例 `BP_ZZGZ_GT_LH_01`）→ 新增
2. 命名 `FACT_一级二级_三级(可省)_名`（范例 `FACT_ZZGZ_GT_LH_01`）
3. 字段铁律：① `REC_ID`(主键/分区/32/非空) ② `LOADER`(100) ③ `LOAD_TIME`(14)；其余为业务度量字段
4. **关联维度（关键绑定）**：勾选需关联的事实模型字段 → 点"关联维度" → 选择步骤2已物化的维度表字段（如 `FACTORY_DIV`→`DIM_ZZGZ_FACTORY_01`、`DATE_CODE`→`DIM_ZZGZ_TIME_01`），并填**维度别名**（与维度模型同名，便于后续勾选）
5. BEDK01 → 事实表页签 → 生成数据表（勾选已关联维度表）→ 物化表 → 上线申请 → 审批 **BEDP1004**

### 步骤 4 原子指标（BEDF54，关联事实明细模型 + 数据域 + 表达式）
1. CDM工作空间 → 原子指标设计 → 新增
2. 命名 `IND_一级二级_指标名`（范例 `IND_ZZGZ_MOLTIRON_WT_01` 铁水用量）
3. **选择事实明细模型**（步骤3的 `FACT_ZZGZ_GT_LH_01`）→ 下方同步字段 → 选函数+字段组成**表达式**，如 `SUM(重量)`（字段来源事实模型）
4. 选**数据域**（如制造域 ZZ00）
> ⚠️ 原子指标只可基于事实明细表（手册p38）；该事实表必经步骤9数据加工从 ODS 落库，禁止绑定 ODS 表。原子指标计算逻辑修改会级联更新所有下游派生指标；被派生引用时不可删除/改名。

### 步骤 5 派生指标（BEDK02，关联原子 + 业务指标 + 统计维度 + 通用限定）
1. 原子指标设计 → 派生指标模型页签 → 新增
2. 命名 `IND_一级二级_原子指标名_派生含义`（范例 `IND_ZZGZ_GT_LH_01_XG`）
3. 必配四项：
   - ① **原子指标**：选步骤4的原子指标（计算口径来源）
   - ② **统计维度**：选维度表中被关联的维度字段——即维度表的**主键或候选键**（如 `DIM_ZZGZ_FACTORY_01.FACTORY_DIV`、`DIM_ZZGZ_TIME_01.DATE_CODE`）→ 该字段即 DWS 汇总时 `GROUP BY` 的字段
   - ③ **时间限定**：日/月/年 或 `$TD$` 当日
   - ④ **通用限定**：DWS 表数据加工时的 `WHERE` 条件（非时间，如 `MAT_CODE='A1200075'`；无则留空）
4. **业务指标绑定**：关联步骤1的业务指标（非过程指标）；纯中间量则过程指标（不选业务指标）
5. 选**数据类型**（派生指标计算结果类型）；默认值策略：无策略/置0/置null/自定义
> 复合指标（可选）：切换"复合指标模型"页签新增，选一个或多个派生指标叠加计算，维度/口径继承派生指标，不得新增维度口径。

### 步骤 9 生成步骤 / 数据加工（自动生成 ODS→DWD、DWS 加工步骤，DB2 语法）

> 平台依据两类配置**自动生成数据加工步骤（BEDD02）**：① **ODS→DWD 事实表加工**——来自 BEDF52 事实模型"映射"(ODS→CDM) 与 BEDK01"生成数据"，专家需在 BEDF52 配置 ODS 源字段映射与清洗/转换（源表如 `T_ODS_TMMSM21/TMMSM2A/TMMSM01/TMMSM11B`）；② **DWS 汇总加工**——来自 BEDK03 汇总表，**统计维度→GROUP BY，通用限定→WHERE**。专家负责核对/补充手写 SQL（遵循 DB2 与乐享 DB2 调优规范），并在数据加工页登记步骤。
>
> ⚠️ **数据起点在 ODS**——绝大多数原始数据存于 ODS 层，事实明细表（DWD）必须经本步骤从 ODS 清洗/转换/关联后落库，禁止把 ODS 直接当事实明细表绑定原子指标。SQL 设计参考乐享知识库·AI赋能团队知识库·DB2数据库知识库的调优文档（索引/Join/UNION/分页/字符长度等）。

**数据加工 SQL 由数仓开发专家负责设计，数据库为 DB2，必须严格遵循 DB2 语法与 5S 平台数据加工规范。** 标准加工模式：**先 DELETE 删除目标 DIM/DWD/DWS 表当日分区数据 → COMMIT → 再 INSERT INTO 目标表（前三列必须是 REC_ID / LOADER / LOAD_TIME）→ COMMIT。**

1. 数据加工 → 选工作空间与目录 → "SQL计算"
2. 目录规范：CDM按二级数据分类建目录；ADS按需从二级数据分类选建（在任务编排页BEDD00右键"+添加"，自动同步）
3. 步骤名称与目标事实表一致，把"T"改为"P"（如目标表 T_DWD_FACT_X → 步骤 P_DWD_FACT_X）

**标准加工模板（DELETE + INSERT + COMMIT，DB2 语法）**：
```sql
/*
| Procedure: P_{DWD|DWS}_FACT_目标表名
| Overview:  {目标表中文名} 数据加工
| Modification History:
|   Date        Who        What
|   2026.08     数仓开发    Created
*/

-- 步骤①：删除目标表当日分区数据（必须加时间等字段限定范围，禁止简单 DELETE 全表）
DELETE FROM {SCHEMA}.{T_DIM|T_DWD|T_DWS}_XXX
WHERE DATE_CODE = TO_CHAR(SYSDATE - 1 DAY, 'YYYYMMDD');  -- 添加时间限制
COMMIT;  -- DELETE 后必须 COMMIT，防锁表

-- 步骤②：插入加工后的数据（前三列固定为 REC_ID / LOADER / LOAD_TIME）
INSERT INTO {SCHEMA}.{T_DIM|T_DWD|T_DWS}_XXX (
    REC_ID,          -- ①主键（必须，第1列）
    LOADER,          -- ②数据装载者（必须，第2列）
    LOAD_TIME,       -- ③数据装载时间（必须，第3列）
    DATE_CODE,       -- 日期代码
    字段4,           -- 业务字段…
    字段5
)
WITH A AS (
    SELECT ...
    FROM {ODS源表1}
    WHERE ...
),
B AS (
    SELECT ...
    FROM {ODS源表2}
    WHERE ...
)
SELECT
    HEX(RAND())                          AS REC_ID,       -- 主键
    '{分区}.{来源表名}'                  AS LOADER,       -- 来源表（多源汇总时按"分区.表名"记录）
    TO_CHAR(SYSDATE, 'YYYYMMDDHH24MISS') AS LOAD_TIME,    -- 装载时间
    A.DATE_CODE,
    A.字段4,
    A.字段5
FROM A
UNION ALL
SELECT
    HEX(RAND())                          AS REC_ID,
    '{分区}.{来源表名2}'                 AS LOADER,
    TO_CHAR(SYSDATE, 'YYYYMMDDHH24MISS') AS LOAD_TIME,
    B.DATE_CODE,
    B.字段4,
    B.字段5
FROM B
;
COMMIT;  -- INSERT 后必须 COMMIT，防锁表
```

**SQL 编写五条铁律（必遵守）**：
```sql
-- a. 每个 DML（UPDATE/INSERT/DELETE）后必须 COMMIT; 防锁表（加工结尾不用加）
-- b. DELETE 历史数据必须按日期等字段限定范围；清全表用 TRUNCATE 代替 DELETE
-- c. 复杂逻辑/多步骤必须注释；每次修改原版逻辑需加注释记录修改历史；注意缩进
-- d. 多ODS表汇总到同一DWD时，LOADER 记录来源表（"分区.表名"形式，
--    如 SGM1M1.TMMHPO1 / SGM1M1.HMMHPO1）；其他情况 LOADER 存放任务名称
-- e. REC_ID 存放主键（可用 HEX(RAND()) 生成）；LOAD_TIME = TO_CHAR(SYSDATE,'YYYYMMDDHH24MISS')
```

**DB2 语法要点**：`SYSDATE - 1 DAY` 日期加减；`TO_CHAR(SYSDATE,'YYYYMMDD')` 8位日期；`TO_CHAR(SYSDATE,'YYYYMMDDHH24MISS')` 14位时间戳；`HEX(RAND())` 生成主键 REC_ID；`NVL/COALESCE` 空值处理；`DECODE/CASE WHEN` 条件映射；`||` 字符串连接；`FETCH FIRST n ROWS ONLY` 分页（不用 LIMIT）；`WITH cte AS (...)` 多步计算；`TRUNCATE TABLE xxx IMMEDIATE` 清全表；统计维度作 `GROUP BY`。

**DB2 调优要点（参考乐享·AI赋能团队知识库·DB2数据库知识库）**——数据加工SQL涉及大数据量时务必遵循：
- **索引与谓词**：WHERE / JOIN / ORDER BY 涉及字段尽量命中索引；避免在索引列上使用函数（如 `SUBSTR(COL,1,8)='...'`），否则索引失效走全表扫描；可改为范围比较或预处理派生列。
- **JOIN 选择**：能 INNER JOIN 就不用 LEFT JOIN；LEFT JOIN 的右表过滤条件要写在 ON 而非 WHERE，避免把左连接退化成内连接或产生非预期 NULL。
- **UNION 与 UNION ALL**：多源 ODS 汇总到同一 DWD 时一律用 `UNION ALL`（去重无意义且开销大），不用 `UNION`。
- **批量与提交**：大批量 INSERT 分批提交，避免单事务锁表/日志爆满；DELETE 必须带日期等范围条件，清全表用 `TRUNCATE TABLE ... IMMEDIATE`。
- **统计信息**：新表/大改后执行 RUNSTATS 更新统计信息，必要时用 `EXPLAIN` / `db2exfmt` 看执行计划，定位全表扫描与高代价步骤。
- **字符长度**：DB2 汉字占 **2 个字符**，定长字段（VARCHAR/CHAR）长度要预留中文占用，导入字段长度超表定义会失败；涉及中文的维度编码/描述字段适当放宽。
- **隔离级别**：只读或允许脏读的场景用 `WITH UR`（Uncommitted Read）降低锁竞争。

4. **血缘配置**：勾选来源表与目的表 → 字段血缘关系配置（拖拽关联字段）→ 保存

**物化 SQL 模板详见最终交付物 HTML**：DWD明细事实表（多源UNION ALL汇总）、DIM维度表（全量刷新TRUNCATE）、DWS指标汇总表（统计维度GROUP BY + 条件SUM）三类完整案例，见 `deliverables/5S平台维度建模全流程开发指南.html` 第⑧章。

## 六、维度建模问题排查流程（报错往前查）

常见报错：汇总表保存报错 / 步骤生成报错（公式解析SQL语法错误）/ 汇总时查不到指标或缺指标 / 查不到维度 / 指标生成SQL维度字段为NULL / 派生指标语句执行报错（如 SQLCODE=-2074, SQLSTATE=42704 表不存在）。

**从最后一步报错处往前排查的标准流程**：
1. **BEDK02**：复合指标"生成数据表"查看SQL并试运行；报错的继续往前；已生成复合指标点修改并试运行（所有用到的复合指标都要查）
2. **派生指标**：按复合指标同样方式全部排查。若派生无问题、复合"生成"的SQL没问题但"已生成"的执行有问题 → 删除已生成的复合指标重新生成，再生成步骤
3. **派生也有问题** → 继续往前到 **BEDF52**：查看维度/事实模型有无修改 → 勾选模型"同步数据元"按提示同步
4. 同步完成后，原子指标、派生指标、复合指标**依次重新保存**（有同步提示就同步）→ 再到 BEDK03 汇总表操作；仍有问题检查派生/复合SQL执行，有问题删除已生成重新生成
5. 重新生成后汇总表需**重新选择指标字段**，再查看生成步骤
6. 以上仍无法解决 → 联系平台支持人员
