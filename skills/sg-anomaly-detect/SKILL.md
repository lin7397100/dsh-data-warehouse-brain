# sg-anomaly-detect · 异常波动检测

## 定位

指标的**哨兵**：用数据自身的历史与业务边界判断"这个值正不正常"。

## 四类检测方法

| 方法 | 适用 | 判定 |
|---|---|---|
| ① 同环比 | 有稳定周期的指标 | 环比偏离 > 5% 关注 / > 15% 异常；同比同理 |
| ② 历史基线偏离 | 波动规律的指标 | `|当前值 - 基线均值| > 3σ` 或超出 P5~P95 区间 |
| ③ 业务合理区间越界 | 有明确物理/工艺边界 | 超出本体专家定义的合理区间（如作业率 > 100%） |
| ④ 固定阈值 | 有硬性管控线 | 超出设定阈值即告警 |

> 多方法并用时取**最严格**判定，并记录各方法结论。

## 严重度分级

| 级别 | 条件 | 处置 |
|---|---|---|
| **P0 严重** | 偏离 > 30% / 越物理边界 / 关键指标缺数 | 立即告警 + 根因分析 + 建任务 |
| **P1 重要** | 偏离 15%~30% / 越业务基线 | 告警 + 标注提示 |
| **P2 关注** | 偏离 5%~15% | 结果中标注，不单独告警 |
| 正常 | 偏离 < 5% 且未越界 | 直接交付 |

## 工作流（四步）

### Step 1 · 确定检测对象与基准

- 对象：指标 + 维度（厂部/产线/炉座/成本中心）+ 时间粒度
- 基准：前一日 / 上月同期 / 历史 N 天分布 / 业务区间

### Step 2 · 执行检测（DB2 MCP 实数据）

```sql
-- 例：近 30 天基线 + 当日值
WITH hist AS (
  SELECT AVG(ZB_VALUE) AS mu, STDDEV(ZB_VALUE) AS sigma
  FROM … WHERE YMD BETWEEN '$D30$' AND '$D2$' AND ZB_NAME=?
)
SELECT 当日值, mu, sigma,
       CASE WHEN ABS(当日值 - mu) > 3*sigma THEN 'P0'
            WHEN ABS(当日值 - mu) > 2*sigma THEN 'P1' ELSE '正常' END AS 等级
FROM …, hist;
```

### Step 3 · 结果解读（关键）

**异常 ≠ 错误**。必须区分：

| 情况 | 判断 | 处置 |
|---|---|---|
| 数据异常但业务真实发生 | 真异常（如检修导致产量下降） | 保留数据 + 说明原因 |
| 数据异常且无业务解释 | 疑似数据问题 | 转 `sg-root-cause-fullchain` |
| 数据"正常"但业务不合理 | 越界检测更可靠 | 用业务区间兜底 |

检测结论必须结合**业务上下文**（检修、限产、品种切换、季节因素）。

### Step 4 · 输出与路由

异常清单 → 质量专家判定 → `sg-agentic-decision` 路由（通知 / 建任务 / 仅标注）。

## 输出规范

```json
{"scope": {"metrics": ["圆棒当日合格量"], "period": "2026-09-01", "factory": "三钢闽光"},
 "method": ["① 同环比", "② 基线偏离"],
 "results": [{"metric": "圆棒当日合格量", "value": 1200,
              "dod": "-20%", "baseline": {"mu": 1500, "sigma": 120},
              "z_score": -2.5, "level": "P1",
              "business_ctx": "当日一棒线检修 6 小时",
              "verdict": "业务真实原因，数据无误"}]}
```

## 注意事项

1. **异常不等于错误** —— 必须结合业务上下文判断，避免"狼来了"。
2. 缺数（NULL / 0 行）按 P0 处理，优先于数值偏离。
3. 成本域语义反转：成本下降是"好"，检测报告中方向标注必须反转。
4. 基线需定期重算（工艺变化后），并记录基线版本与样本区间。
